## 3-1. 협업과제 소개  〔평가: 과제 이해도〕

### 제안 배경 — "왜 소크라틱 튜터인가"
- **모순에서 출발**: 공부와 게임의 원리는 같은데, 왜 게임은 시키지 않아도 하고 공부는 시켜도 안 하는가? 핵심 차이는 **자기참조성**(학습 소재가 학습자 자신에게서 나오는 정도)이다.
- **학습과학의 정설**: 백지에서 산출하는 **인출(retrieval)** 만이 학습을 자동화하며(Kang et al., 2013), 단순 반복보다 우월하다(Karpicke & Blunt, 2011). 그러나 인출은 높은 인지부하를 수반해(Bjork, 1994) 모바일에서 이탈을 부른다.
- **시장의 빈칸**: 글로벌 언어학습 시장 60조원(국내 1조)인데 **D30 리텐션 약 2%** — 게임화·스트릭은 '학습 없는 가짜 재방문'에 그치고, 학습과학은 인지부하로 이탈을 유발. **'학습이 동반된 지속'은 미해결 빈칸.**
- **해법**: 난이도를 낮추지 않고 **자기참조성으로 동기를 공급** → 학습효과와 지속을 동시 달성. 정답을 바로 주지 않고 **스스로 답을 떠올리게 유도하는 소크라틱 방식**이 인출 학습의 핵심 구현체.
- **왜 지금/왜 LLM**: 자유로운 자기표현을 실시간 교정해야 인출 학습이 가능한데, 이는 **LLM 등장으로 비로소 실현**되었다(Kittredge et al., 2025).

### 제품(서비스) 개요
- **언어의숲(영어의숲)**: 유저의 **일상 일기(텍스트)+사진**을 소재로 학습하는 개인화 언어학습 AI. iOS·Android 출시('25.12), KAIST 데이터전략연구실 창업팀.
- Agent 정체성 = **"유저를 깊이 아는 외국인 친구"**: 단순 교정기가 아니라 일기·사진으로 관심사·성격·맥락(페르소나)을 이해하고 그 위에서 소크라틱 튜터링.

### 주요 기능 (= 업스테이지 세부과제 ①②③에 1:1 대응)
| 세부과제 | 우리 기능 | 내용 |
|---|---|---|
| ① 오개념 진단 | `persona-analyzer` | 일기·답안에서 오류패턴·멘탈모델·CEFR 진단(진단표 5패턴: opener·시제/상·명사화·강조·형식) |
| ② 소크라틱 발문 | `socratic-tutor`(메인) | 정답 즉시 노출 X, 단계적 유도질문 생성, 친구 톤, **되묻기 금지 계약** |
| ③ 개인화 RAG | `dossier` + RAG | 학습이력(persona·language_profile·error_log·timeline)을 검색·주입해 다음 발문 개인화 |

### 성능(실측·검증된 출발점) 🟡[보강: 표/그래프]
- 프롬프트 채점 품질 **v1 81.3 → v1.2 92.1점**(오류 30%↓), '되묻기 0점 버그'를 입력슬롯 분리로 해결.
- 서비스 지표: **D1 리텐션 30.1%**(동종업계 평균 대비 2배, '26.5), 출시 1개월 매출 900만원(공헌이익 흑자).

## 3-2. 협업과제 기술 경쟁력  〔평가: 기술경쟁력·개발역량 / Solar 활용성〕

### 보유기술의 혁신·우수성
- **검증 가능한 설계(측정 기반 LLMOps)**: "GPT 래핑 아니냐"에 대한 답 = 계약 테스트(되묻기·형식 위반 자동검출, 블로킹 게이트) + 6축 품질 eval(골든셋) + 관측(usage·p95). 실측 리포트로 운영 중.
- **프로바이더 비종속 라우터**: LLM을 라우터 뒤 **교체 가능한 부품**으로 설계(기존 OpenAI↔OpenRouter failover 자산 승격). → **Solar LLM을 모델 슬롯에 그대로 투입 가능**.
- **독점 데이터(moat)**: 유저의 일기+사진. 소재가 유저 자신에게서 나와 동기·애착의 원천(단순 데이터량이 아님).

### 경쟁기술 대비 차별성
| 구분 | 일반 GPT 챗봇 / 타 에듀테크 | 언어의숲 |
|---|---|---|
| 학습 소재 | 정해진/외부 콘텐츠 | **유저 자신의 일기·사진(자기참조)** |
| 피드백 | 정답 즉시 제공(따라하기) | **소크라틱 발문 — 백지 인출 유도** |
| 개인화 | 시스템이 맞춤(적응형) | **학습자가 의미 생산 주체(자기참조성)** |
| 품질관리 | 비측정 | **계약 게이트·6축 eval·골든셋** |
| 측정 | 재방문율(가짜 재방문) | **상태전이·인출세션비율·자기참조 ratio(학습 동반 지속)** |

### Solar / Document Parse / Information Extract 활용 (★Solar 활용성)
- **Solar LLM**: socratic-tutor·persona-analyzer 모델 슬롯에 투입 → 발문 생성·오개념 진단 추론 엔진. 골든셋 기반 파인튜닝으로 교수법 특화. 🔴[확인: 한국어 일기→영어 교정 품질, 멀티모달(사진) 처리 방안]
- **Document Parse**: 🟡 학습 교재·문법 레퍼런스 등 문서를 구조화해 RAG 지식베이스 구축에 활용.
- **Information Extract**: 🟡 일기/답안에서 오류패턴·학습 이력 구조화 추출(dossier 자동 갱신)에 활용.

### 완성 수준
- 앱 출시·운영 중(PMF 검증·스케일업 단계). 프롬프트 운영 시스템(진단표·정답셋·채점 하네스) 작동 중 → **0에서 시작 아님**. 본 과제로 에이전트화 + Solar 전환 + 측정 자율화.
