# Spark Claw (SparkLabs) 지원서 작성 워크플로우

> 목적: **실제 지원서 폼**을 기준으로 ① 목차 골자, ② 각 항목에 무엇을 써야 하는지,
> ③ 작성에 필요한 입력 정보, ④ 빈칸 → 제출까지의 작성 프로세스를 정리한 실행 문서.
>
> ⚠️ 이 문서는 **답변 내용을 대신 쓰지 않습니다.** 목차의 골자와 "무엇을/어떤 근거로 써야 하는가"만 잡습니다.
> 실제 답변은 [§3 필요 정보](#3-내가-받아야-할-정보-founder-input)를 채워주시면 그걸 근거로 함께 작성합니다.
>
> _Reels 프로젝트와 무관, 보관 목적으로 이 레포에 둠._

## 0. 프로그램 한 줄 요약

- **성격:** AI 스타트업 대상으로 보이는 SparkLabs 트랙(질문에 "AI 없이 이 문제를 어떻게 해결?"이 명시). 즉 **AI가 핵심인 솔루션**임을 전제로 심사.
- **심사 코어 3축:** ① 문제·솔루션의 명확성 ② **실제 검증(현장 근거)** ③ **실행 속도·팀 역량**. 폼 전반이 "말"이 아니라 "증거와 실행"을 묻는다.
- **자격(공개 정보):** 창업 3년 이내, 공동창업자 필요, 지분 약 6%(SAFE/CPS). → 지원 직전 공식 공고로 재확인.

## 2. 항목별 — "무엇을 써야 하나" (골자만)

> 실제 문장이 아니라 **각 칸에 담겨야 할 요소**를 정리. 작성 시 이 골자를 채우는 방식으로.

### 섹션 2 — Problem & Solution
- **2-1 시장·문제:** 타겟 = `누구(페르소나)` / 그가 `언제·어떤 상황`에서 / `무엇이 얼마나 불편한지`를 **정량·구체**로. (예: "주 N회, 매번 X분 소요" 식 수치) — 형용사 금지, 장면 묘사.
- **2-2 솔루션:** 그 Pain을 **어떻게** 없애는지. 핵심 기능 1~3개 + **AI가 정확히 어디서 가치를 만드는지**. "무엇을 만들 것"보다 **"이미 작동하는 것"**.
- **2-3 검증(가장 중요):** 수요가 진짜임을 **현장 증거**로. 우선순위: ① 유료 결제/재구매 ② 파일럿·계약 ③ 리텐션·사용빈도 ④ 유저 인터뷰 인용 ⑤ 대기자. **숫자 + 인용** 한 묶음.
- **2-4 대안 & 차별점:** 유저의 **현재 대체 행동**(수기·기존 앱·과외 등)을 먼저 인정 → 우리만의 **차별점(왜 더 낫고, 왜 안 베껴지는가)**. "경쟁자 없음" 금지.
- **2-5 팀-문제 적합성:** 대표·핵심팀원별 `도메인 경험 / 기술 / 네트워크 / 차별 이력`을 **이 문제와 연결**. unfair advantage 1개는 분명히.
- **2-6 2~3개월 목표:** **측정 가능한 목표 1~3개** + 그에 도달할 **주차별/단계별 실행계획** + 현재 팀에 **부족한 포지션과 그 이유**(솔직하게).

### 섹션 3 — Execution & Validation
- **3-1 결과물:** 팀 결성 이후 만든 것의 **목록 + 수치**. (MVP 상태, 누적/활성 유저, 유료 고객 수, 인터뷰 N건, 매출/계약). 시간순 마일스톤으로.
- **3-2 최근 2주 수정 사례(실행속도 테스트):** `발견한 문제 → 무엇을 바꿨나 → 결과(지표 변화)` 1~2개. **빠른 학습·실행**을 증명하는 칸 — 추상적 계획 말고 **실제로 한 일**.
  - ⚠️ 현재 초안에 "해외 확장"만 적혀 있는데, 이 질문은 **2주 내 제품/전략 수정 사례**를 묻는 것이라 의도와 어긋남. 작은 실험이라도 구체 사례로 교체 권장.
- **3-3 병행 여부:** 풀타임이면 X(없음)이 신뢰에 유리. 사실대로.

### 섹션 5 — 기타
- **5-1 기대하는 도움:** **복붙 금지.** Spark Claw 특성(PMF 코칭·후속투자·네트워크)에 **우리의 구체적 니즈**(2-6 목표와 연결)를 매칭. "투자금"만 적지 말 것.
- **5-2 / 5-3 드롭다운:** 옵션 확인 후 가장 정직한 선택.

### 섹션 1·4 (미확인)
- 캡처 확보 후 본 문서에 골자 추가.

## 3. 내가 받아야 할 정보 (Founder Input)

> 아래를 채워주면 그걸 **근거로** 각 칸 초안을 함께 잡습니다. 모르면 `?`로 두고 진행.

### A. 기본
- [ ] 회사명 / 설립일(3년 이내 확인) / 공동창업자 유무
- [ ] 제품 한 줄 소개 + 앱/웹 링크, 데모 영상

### B. 시장·문제 (→ 2-1, 2-4)
- [ ] 핵심 타겟 고객 페르소나 (구체적으로 1순위 1명)
- [ ] 그가 겪는 Pain Point + **빈도/소요시간/비용** 등 수치
- [ ] 지금 그 사람이 쓰는 **대안/대체 행동**

### C. 솔루션 (→ 2-2)
- [ ] 핵심 기능 1~3개
- [ ] **AI가 정확히 어디서, 어떻게** 가치를 만드는가
- [ ] 기존 방식 대비 차별점 + 모방 난이도(해자)

### D. 검증 지표 (→ 2-3, 3-1) — **가장 중요, 숫자 위주로**
- [ ] 누적/활성 유저(MAU·DAU), 리텐션(D7/D30 등)
- [ ] 유료 고객 수 / 매출(MRR) / 전환율
- [ ] 유저 인터뷰 건수 + 인상적 **인용 2~3개**
- [ ] 파일럿/계약/대기자 등 기타 근거

### E. 팀 (→ 2-5, 2-6)
- [ ] 대표·핵심팀원 이력(도메인 경험·기술·네트워크·이전 성취)
- [ ] 현재 부족한 포지션 + 왜 필요한지

### F. 실행 (→ 2-6, 3-1, 3-2)
- [ ] 향후 2~3개월 **측정가능 목표** 1~3개
- [ ] **최근 2주** 안에 유저 피드백/데이터로 바꾼 일 (문제→수정→결과)
- [ ] 본 프로젝트 외 병행 업무 여부

### G. 프로그램 (→ 5)
- [ ] Spark Claw에 **구체적으로 바라는 것** (코칭/투자/네트워크 등)
- [ ] 알게 된 경로

## 4. 작성 워크플로우 (빈칸 → 제출)

```
[0 폼 완성] → [1 정보수집] → [2 핵심메시지] → [3 칸별 초안]
                                                   │
                       ┌───────────────────────────┘
                       ▼
              [4 검토 루프 ×2~3] → [5 다듬기·제출]
```

**Step 0 — 폼 목차 완성**
- 섹션 1·4 캡처 → [§1 표](#1-폼-목차-골자-실제-양식-기준) 빈칸 채우기. 글자수 제한·드롭다운 옵션도 메모.

**Step 1 — 정보 수집**
- [§3 Founder Input](#3-내가-받아야-할-정보-founder-input) 채우기. 빈칸·`?`는 "확보해야 할 데이터"로 별도 표시.

**Step 2 — 핵심 메시지 1줄 고정**
- "우리는 `[타겟]`의 `[문제]`를 `[AI 솔루션]`으로 해결하고, `[핵심 검증 지표]`로 증명한다." → 모든 칸이 이 한 줄과 일관되게.

**Step 3 — 칸별 초안 (섹션 2 → 3 → 5 → 1 → 4 순서 추천)**
- 검증·실행(2-3, 3-1, 3-2)이 합격을 가르므로 **여기에 시간 집중**. 숫자 없는 칸은 `[TODO: 데이터]`.

**Step 4 — 검토 루프 (2~3회)**
- 자가 점검 → 사업 모르는 동료 1명 → (가능하면) 선배 창업자/멘토. 매 회 [§5 체크리스트](#5-제출-전-체크리스트)와 대조.

**Step 5 — 다듬기 & 제출**
- 형용사 삭제·수치 최신화·링크 점검 → 개인정보 동의 → **마감 2일 전 제출**.
