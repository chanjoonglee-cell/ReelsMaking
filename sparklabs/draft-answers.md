## 2. Problem & Solution

### 2.1 타겟 시장 / 고객 / Pain Point
저희가 푸는 문제는 **언어학습 시장의 고질적 이탈(churn) 문제**입니다. 글로벌 언어학습 시장은 약 60조 원 규모로 꾸준히 성장하지만, 업계 평균 D30 리텐션은 2% 수준 — 즉 **98%가 이탈**합니다. 시장이 커도 '진짜 문제'가 풀리지 않았다는 신호입니다.

이탈의 원인은 유저의 의지가 아니라 **잘못된 학습경험 설계**입니다. 이탈 유저 인터뷰 결과, 기존 앱은 ① 관심 없는 소재 ② 수준에 맞지 않는 난이도 ③ 기억에 남지 않는 방식(쉐도잉·반복) ④ 심리적 부담·거부감 — 이 **4가지 중 하나만 걸려도 이탈**했습니다.

1순위 타깃은 **영어가 능숙하지 않은, 영어권 거주 한인 중년 여성**입니다. 이들은 회사·자녀 학교·병원 등에서 매일 영어가 필요하지만 한국적 사고를 영어로 표현하는 데 막막함을 느끼고, 아침·자기 전 집에서 하루 5~10분 학습합니다. 특히 해외 생활의 외로움 속에서 **자기 일상을 표현하는 행위 자체가 정서 회복(멘탈케어)** 이 되기에, 이들에게 저희 서비스는 '습관성 멘탈케어앱'에 가깝습니다.

### 2.2 솔루션
많은 앱이 '무조건 많이 말한다'는 방식으로 잘못 접근하지만, 학습과학적으로는 **'한 문장이라도 스스로 생각해 표현(인출)'** 할 때 장기기억이 형성됩니다.

그래서 영어의숲은 영어를 '가르치는' 앱이 아니라 **'영어로 자신의 일상과 감정을 교감하는' 앱**입니다. 인지심리학·학습과학·데이터/AI를 기반으로, 유저의 일상을 영어로 표현하게 만드는 학습 메커니즘을 설계했습니다.

한 세션(자기 전 5분)의 흐름:
1. **일상 데이터 입력** — 오늘 있었던 일을 사진·텍스트로 기록
2. **소재 추천 & 난이도 자동화** — 유저 수준에 맞는 표현 과제 자동 생성
3. **인출 기반 학습(문장 만들기)** — 직접 영어 문장을 만들면 즉시 점수 + "원어민은 이렇게" 교정 (*Today I ate pasta* → *I had some vongole pasta*)
4. **정서 데이터 시각화** — 학습 기록을 다이어리·캘린더로 축적, 효능감 강화 → 재방문

이 메커니즘으로 **D1 리텐션 약 30%, D30 리텐션 약 15%** 를 달성, 동종업계 평균 대비 **2~5배** 높은 리텐션을 입증했습니다.

### 2.3 수요 검증 (현장 근거)
**PMF 검증을 완료**했습니다.
- **리텐션:** D1 ~30%(GA 기준, 업계 2배) / D30 ~15% — 동종 대비 2~5배. 광고 0원에서 1개월간 오가닉 재방문 유지.
- **유료 결제:** 유료 기능 출시 **1개월 만에 월 매출 900만원**, 공헌이익 흑자. ARPPU 55,292원, 결제전환율 [3.3%].
- **정성:** 모바일 언어학습 이탈 유저 인터뷰 다수 → 4대 이탈요소 도출.
- **수요 강도:** 해외 유저 결제전환이 국내 대비 약 [2.5]배 → 별도 마케팅 없이도 해외에서 강한 수요 확인.

→ 일시적 관심이 아니라, **유저가 자발적으로 돌아오는 습관이 형성**된 패턴입니다.

### 2.4 기존 대안 대비 차별점
현재 유저들의 대안과 한계:
- **듀오링고·말해보카**(정해진 콘텐츠·마이크로러닝): 내 일상과 무관해 기억에 안 남음
- **링글·스픽**(말하기 중심): 비용·심리적 부담, '무조건 많이'
- **ChatGPT 등 범용 AI**: 대다수 유저가 '프롬프트' 개념조차 모르고, 안다 해도 매번 맥락 입력이 번거로움

핵심 차별점:
1. **개인 데이터 × 마이크로러닝 동시** — 경쟁사는 사분면 한쪽에만, 영어의숲은 "개인화 + 짧게"의 우상단 점유
2. **'학습의 배달'** — 누구나 ChatGPT로 요리(프롬프트)할 수 있지만, 번거로움 없이 **보장된 퀄리티**를 받기 위해 배달을 시킴
3. **데이터 해자** — 쓸수록 일상·정서·수준 데이터가 쌓여 대체 불가, 경쟁이 아닌 보조교재로 상호보완하며 락인

## 4. Technical Capability

### 4.1 가장 복잡했던 코드/시스템
가장 복잡했던 부분은 **LLMOps 기반의 AI Agent 파이프라인** 설계입니다.

**왜 어려웠나:** 유저가 자유롭게 쓰는 일상 문장은 입력이 사실상 무한대라, 단일 프롬프트로는 ① 번역·교정 품질이 들쭉날쭉(할루시네이션) ② 응답 지연(latency) ③ 비용 폭증 — 세 문제가 동시에 발생합니다. 학습 서비스 특성상 **틀린 영어 교정은 치명적**이라 품질을 일정하게 보장해야 했습니다.

**어떻게 해결했나:** 하나의 거대한 호출 대신 작업을 **여러 단계의 에이전트로 분해**했습니다 — [예: 입력 분류 → 난이도 판정 → 문장 교정·대안 생성 → 채점 → 검수]. 각 단계에 **적합한 모델을 라우팅**하고, 출력 검증 단계를 두어 할루시네이션을 통제했습니다.

> 첨부: [GitHub repository 링크] / [Claude Code·Cursor 개발 로그] — 없으면 X. (AI 트랙이므로 가능하면 공개 권장)

### 4.2 AI 성능 최적화 (범용 API 호출 그 이상)
단순 API 호출이 아니라, **LLMOps 파이프라인으로 품질을 측정·최적화**합니다. 언어학습 서비스는 다음 **3가지 지표**를 정의해 검수합니다.

1. **번역·교정 정확도** — 잘못된 교정을 막기 위한 핵심 품질 지표 (할루시네이션 통제)
2. **출력 시간(latency)** — 5분 학습 경험을 해치지 않는 응답 속도
3. **비용** — 단계별로 적정 모델을 선택해 건당 비용 절감

**최적화 방법:** [프롬프트 엔지니어링 / 모델 라우팅 / 평가셋 구축 / RAG·파인튜닝 여부] 를 통해 위 3지표를 개선했습니다.

**정량 결과 (최적화 전 → 후):**
- 번역·교정 오류율: [X% → Y%]
- 평균 latency: [X초 → Y초]
- 건당 비용: [X원 → Y원]

> ⚠️ 이 칸은 **before→after 숫자가 핵심**입니다. 평가셋 규모·측정 방법과 함께 실제 수치를 채워야 4.2의 설득력이 완성됩니다.

## 5. 기타

### 5-1 Spark Claw 프로그램으로 기대하는 도움 (자유 서술)
영어의숲은 LLM을 핵심 엔진으로 쓰는 AI 네이티브 제품으로, **AI 비용·품질·속도가 곧 제품 경쟁력이자 런웨이**입니다. 그래서 다음 세 가지를 기대합니다.

1. **Anthropic Claude · AWS 크레딧** — 저희는 AI 품질을 번역 정확도·latency·비용 3개 지표로 관리하는데, 모델·인프라 크레딧은 **건당 비용을 직접 낮춰** LLMOps 파이프라인을 더 공격적으로 고도화하고 런웨이를 늘려줍니다. (배치 기간 핵심 목표와 직결)
2. **해외(영미권) 그로스 PMF 코칭** — 최근 데이터 기반으로 해외로 타깃을 전환했고, 해외 결제 검증이 다음 분기 최우선 과제입니다. SparkLabs의 PMF 중심 1:1 코칭과 글로벌 네트워크가 이 검증을 가속할 적임이라 판단했습니다.
3. **후속 투자·네트워크** — 검증된 해외 수요를 스케일업하기 위한 후속 투자 연계와 파트너 네트워크.
