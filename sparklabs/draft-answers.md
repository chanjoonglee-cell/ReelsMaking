## 2. Problem & Solution

### 2.1 타겟 시장 / 고객 / Pain Point
저희가 푸는 문제는 **언어학습 시장의 고질적 이탈(churn) 문제**입니다. 글로벌 모바일 언어학습 시장은 약 60조 원으로 성장 중이지만, 언어학습 앱의 D30 리텐션은 평균 2~3% — **100명이 들어오면 98명이 한 달 안에 떠납니다.** '공부는 원래 어렵다'로 치부할 수 있지만, 이탈 유저를 리서치해보니 진짜 원인은 의지 부족이 아니라 **잘못된 학습경험 설계**였습니다.

언어학습의 본질적 목적은 **'내 생각을 외국어로 표현하는 것'** 인데, 대부분의 앱은 '나와 무관한' 콘텐츠를 학습시킵니다. 자신과 관련 없는 소재, 맞지 않는 난이도, 열심히 해도 기억에 남지 않는 방식(쉐도잉·객관식 퀴즈) 탓에 흥미와 효능감을 잃고 이탈하는 것이 당연합니다. 그래서 저희는 **'나의 이야기를 표현하게 하는 것'** 을 핵심 목표로 삼았습니다.

1순위 타깃은 **영어가 능숙하지 않은, 해외 거주 한인 중년 여성**입니다. 이들은 회사·자녀 학교·병원에서 매일 영어가 필요하지만 한국적 사고를 영어로 표현하기 막막하고, 해외 생활의 외로움 속에서 자기 일상을 표현하는 행위 자체가 정서 회복(멘탈케어)이 됩니다. 나아가 영어를 넘어 **한국어·불어 등 다국어를 아우르는 언어학습 플랫폼**으로 확장하는 것이 목표입니다.

### 2.2 솔루션
영어의숲은 유저의 일상(일기)을 영어로 표현하게 돕는 **인출(retrieval) 기반 개인화 학습 에이전트**입니다.
1. 유저가 오늘 있었던 일상·사진을 기록하면
2. AI가 관심사·난이도·오류 패턴을 분석해 유저가 배우고 싶은 문장을 제시하고
3. 그 문장을 영어로 표현하는 과정에서 즉각 교정을 제공합니다.

핵심은 두 가지입니다. ① 남이 아닌 **'나의 이야기'를 소재로** 삼아 흥미를 유발하고, ② 공부하는 느낌이 아니라 실제로 기억에 남는 **인출(Retrieval) 기반 학습**으로 적은 시간으로도 깊게 각인시킵니다. 즉 영어를 '가르치는' 앱이 아니라, **영어로 자신의 일상과 감정을 교감하며 나를 표현하는 습관을 만드는 앱**으로 재설계했습니다. (인지심리학·학습과학·데이터/AI 기반)

이 메커니즘으로 **D1 리텐션 30%, D30 리텐션 15%** — 동종업계 평균 대비 **2~5배** 높은 재방문율을 입증했습니다.

### 2.3 수요 검증 (현장 근거)
정성·정량 분석으로 모두 수요를 검증했습니다.
- **정성:** 유저 **50여 명 인터뷰** → 이들이 원하는 가치가 "내 생각을 유창하게 외국어로 표현하는 것"임을 확인하고, 이를 제품의 핵심으로 삼아 출시했습니다.
- **정량:** '나의 이야기' 기반 학습이 실제로 재방문·결제로 이어짐을 확인 — 유료 기능 출시 **1개월 만에 월 매출 900만원**(공헌이익 흑자), D1 30%·D30 15%(동종 2~5배), 광고 0원에서 1개월간 오가닉 재방문 유지.
- **수요 강도:** 별도 마케팅 없이도 해외 결제전환이 국내 대비 약 2.5배 → 강한 잠재 수요 확인.

### 2.4 기존 대안(AI 없이) 대비 차별점
영어 학습은 AI 없이도 가능은 하지만, **혼자 하기엔 매우 복잡하고 어렵습니다.** 특히 다음 3가지는 사람이 매우 성실해야만 가능합니다.
1. **내가 관심 있는 소재 찾기**
2. **나에게 적절한 난이도로 학습하기**
3. **복습해야 할 시점에 다시 떠올리기**

저희는 이 과정을 **AI로 전부 자동화·최적화**합니다 — 학습자의 페르소나를 분석해 관심 소재를 추출하고, 수준에 맞는 난이도를 자동 조정하며, 복습 타이밍에 자동 푸시 알림까지 보냅니다. 반면 듀오링고·쉐도잉류는 '무조건 많이 말하라'는 식이라 유저에게 부담만 주고, ChatGPT 같은 범용 AI는 대다수 유저가 프롬프트 개념조차 몰라 활용하지 못합니다. **쓸수록 쌓이는 개인 데이터가 대체 불가능한 해자**가 됩니다.

### 2.5 팀 (문제 적합성)
**연구와 기술(개발)을 동시에 수행하는 기술창업팀**입니다.
- **이찬중 (대표):** 에듀테크·게임 업계에서 약 3년의 현장 경험을 쌓는 과정에서 **'교육과 게임의 몰입 원리가 동일하다'** 는 통찰을 얻었고, 그 직관을 논리로 정립하기 위해 현재 **KAIST 데이터전략 연구실**(국내 최고 전략기관 중 하나)에서 연구 중. 인지심리·학습과학 전공, 대통령과학장학생.
- **서동재 (CTO):** 서울대 수리과학·전기전자, 풀스택 40+회(웹·앱·AI·블록체인), 실시간·결제 시스템.
- **김지아 (Product Designer)** / **김민주 (FrontEnd, Gamification 4회)** / **이상윤 (자문, KAIST 문술미래전략대학원 부교수)**

다른 팀원들도 교육 문제에 강한 문제의식을 공유합니다. KAIST 데이터전략 연구실 MOU·특허출원(10-2025-0146995)으로 기술 기반도 확보했습니다.

### 2.6 향후 2~3개월 목표 / 실행계획 / 필요 채용
핵심 지표는 **LTV/CAC** (LTV=유저당 결제 기여, CAC=유저당 획득 비용)입니다.

**3개월 목표 (측정 가능):**
1. **LTV/CAC 4.73 → 6.0** (BEP 사정권 진입)
2. **해외(영미권) 결제 검증** — 현재 해외 비중 40%+를 기반으로 결제 비율·ROAS 안정화

**실행계획:** R&D로 리텐션·AI 품질을 먼저 끌어올린 뒤 발생 매출을 재투자하는 구조. 해외 한인 커뮤니티 오가닉 + 소액 UA 병행.

**필요 채용:** **그로스/퍼포먼스 마케터(해외 UA 최적화).** 제품 지표는 우상향 중이나, 검증된 해외 수요를 매출로 전환할 획득 채널 전문성이 가장 시급합니다.

## 4. Technical Capability

### 4.1 가장 복잡했던 코드/시스템
가장 복잡했던 부분은 언어의숲 AI를 **상태 없는(stateless) 단발 호출** 구조에서 **유저를 기억하고 개인화하는 에이전트 아키텍처**로 재설계한 일이었습니다. 기존 구조는 매번 프롬프트를 인라인으로 박아 LLM을 한 번 호출하고 끝나, 유저에 대한 기억도 일관된 페르소나도 없었습니다.

**가장 어려웠던 지점은 컨텍스트 관리**였습니다. LLM의 컨텍스트 윈도우는 유한해서, 유저의 누적 일기·사진·오류 이력을 원시(raw)로 다 넣으면 비용·지연·노이즈가 폭발하고, 안 넣으면 개인화가 불가능합니다. 이를 관심사·성격·CEFR 레벨·오류 패턴을 구조화한 **압축 페르소나 dossier**를 1차 컨텍스트로 주입하는 방식으로 풀었고, **일기가 쌓일수록 dossier가 풍부해져 개인화가 강해지는 복리 루프**로 설계했습니다.

또한 특정 모델·SDK 종속을 피하려 OpenAI↔OpenRouter failover를 **단일 라우터**로 승격해 LLM을 '교체 가능한 부품'으로 두고, 에이전트 루프·상태·도구는 백엔드(NestJS)가 소유하게 했습니다. 그 위에 무거운 비동기 분석(페르소나·복습)과 가벼운 실시간 대화(채점·문제 생성)를 **2평면·4서브에이전트**로 분리해 각자 독립된 프롬프트 계약·입출력 스키마·모델 슬롯을 갖도록 했습니다. 설계·문서화에는 **Claude Code**를 활용해 코드·실측 리포트·로그를 분석하고 아키텍처 문서를 자동 생성·동기화했습니다.

GitHub — 아키텍처 설계 문서: `docs/language-learning-agent-strategy.md` / 머지된 코드(계약 테스트 게이트): `languageforest-backend` PR #79

### 4.2 AI 성능 최적화 (범용 API 호출 그 이상)
범용 API 단순 호출에 그치지 않고, **프롬프트 변경이 측정을 통과해야만 배포되는 LLMOps 파이프라인**을 직접 구축했습니다. 언어학습 품질은 ① 번역 오류 ② 출력 시간(latency) ③ 비용(적정 모델) 3축으로 측정·검수합니다.

- **프롬프트 엔지니어링:** 유저 오류를 5개 패턴(opener 남용·시제/상·동사 명사화·강조 누락·정상)으로 분류한 진단표를 입력 조건으로 삼아 v1 → v1.1 → v1.2로 버전 관리하며 개선.
- **데이터셋·평가지표:** KR↔EN 자연어 쌍 골든셋 + 6축 채점 하네스(`run_eval.py`). 평가 오염 방지를 위해 예시셋·정답셋 분리, 채점은 temperature=0·다회 평균으로 신뢰도 확보.
- **계약 테스트(핵심):** 1차 측정에서 v1이 번역 대신 *"Sure! Please provide the text…"* 같은 메타 응답을 반환해 라이브 유저가 빈 응답을 받는 버그를 발견. 이를 **LLM 호출 없는 결정론적 detector**(`isNonTranslationResponse()`)로 만들어 15개 계약 테스트(되묻기·빈 응답 9건 차단 + 정상 6건 통과)로 박고, 프롬프트 설정(`openai.config.ts`)을 건드리는 PR에서 실패 시 **머지를 막는 블로킹 게이트**(`prompt-contract.yml`)로 운영. 원칙은 **계약(블로킹) vs 품질(report-only) 분리**.

**정량 결과:** 채점 정확도 **81.3 → 92.1점(오류율 약 30% 감소)**, 응답 지연 **p95 1.64s → 0.85s**(`gpt-4.1-mini` 라우팅 + 멀티콜 병렬화·스트리밍). 끝으로 유저 피드백(#feedback) → 태깅 → 오류 패턴 매핑 → 골든셋 확장 → 재평가로 이어지는, **사람이 감독하되 데이터로 스스로 커지는 자율 개선 루프**를 설계해 최적화가 일회성에 그치지 않게 했습니다.

## 5. 기타

### 5-1 Spark Claw 프로그램으로 기대하는 도움 (자유 서술)
1. **AI 프롬프트 엔지니어링 / LLMOps 고도화** — 현재 자체적으로 파이프라인을 운영하고 있으나, 더 나은 전문가의 도움으로 품질·비용·속도를 한 단계 끌어올리고자 합니다. (Anthropic Claude·AWS 크레딧은 AI 비용을 직접 낮춰 이 고도화와 런웨이에 직결됩니다.)
