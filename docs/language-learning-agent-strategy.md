## 0. 목적 & 비전

기존 **모바일 영어일기 앱**(겉으로는 영어 일기 앱, 언어의숲)에 AI Agent를 도입한다.
유저로부터 **일기(텍스트)+사진**을 받는다 — 이것이 **독점 데이터(moat)**.

Agent의 정체성: **"유저를 깊이 아는 외국인 친구"**. 단순 교정기가 아니라 일기·사진을
분석해 **멘탈모델·관심사·성격·사고 깊이·삶의 맥락**을 이해하고 그 위에서 외국어를
교정·학습 지원한다. 궁극 목표: **"어려움에도 불구하고 계속 학습하게 만드는 것."**

핵심 기능 4개: ⓪페르소나 분석(중심) ①맞춤 문제·문장 생성 ②소크라테스식 피드백·문답
③망각곡선 기반 복습. 기반 기술: **Claude Agent SDK**.

## 1. 현황 진단 (As-is) — 현재 운영 코드 직접 분석

> 추측이 아니라 현 레포(릴스 생성기 = 언어의숲 현 운영 코드)를 읽고 진단함.

### 스택 · 모델
- **Provider: OpenAI SDK `^4.47.1`, 모델 `gpt-4o`(텍스트+비전).** ⚠️ Claude 아님 → **마이그레이션 갭 존재**
- 런타임: Node.js(CommonJS). 진입점 2개 — CLI(`src/index.js`) + Express 웹서버
  (`src/server.js`, multer 업로드 + SSE 진행률)
- 전처리: `sharp`(512px 리사이즈→base64), ffmpeg 영상 합성

### LLM 호출 패턴
- **고정 5단계 선형 파이프라인.** 에이전트 루프·도구 사용·서브에이전트 **없음**
- **프롬프트가 코드에 하드코딩 인라인**(`analyzeMood.js` systemPrompt). 버전관리·레지스트리 없음
- 재시도: 지수 백오프(429/5xx, 3회) — **모듈마다 `withRetry` 중복 복붙**(공통 유틸 부재)
- 구조화 출력: 전부 **수동** — `JSON.parse`+정규식 폴백+화이트리스트(`VALID_MOODS`),
  점수 1~10 클램프, 실패 시 중립값 폴백. structured outputs/strict **미사용**

### 비용 · 관측
- 비용: **휴리스틱 상수**($0.00425/사진, $0.01/무드분석)로 사전 추정 + 사용자 확인.
  **실제 `usage` 토큰 기반 측정·사후 트래킹 없음**
- 로깅: `console.log` 사람용 한/영 진행 로그. **구조화 로그·트레이싱·세션ID·분석 이벤트 없음**
- 별도 모니터링/분석 연동 없음

### 평가 · CI
- `scripts/test-pipeline.js`는 이름만 "test" — **API 없이 ffmpeg만 검증**(합성 사진).
  **LLM 출력 품질 eval·회귀테스트 전무**
- 골든셋·eval 데이터셋·프롬프트 평가 없음. CI 게이트·lint 없음
- 시크릿: `.env` 단일 `OPENAI_API_KEY`

### 데이터 자산
- `input/diaries.json`(일기) + `input/photos`(사진) = 독점 데이터의 원형.
  단 **라벨링·골든셋 미구축**

### 진단 요약 — 성숙도: **기본 수준**
호출+재시도+휴리스틱 비용추정+진행로깅은 있으나, **프롬프트 버전관리·LLM eval·
관측/트레이싱·실측 비용·회귀테스트·가드레일은 부재.** 또한 **OpenAI 고정 파이프라인**이라
Claude Agent SDK 에이전트로 가려면 마이그레이션이 필요.
→ **에이전트로 넘어가기 전에 LLMOps 토대부터 깔아야 한다**(책: "에이전트 전에
폴더 정리와 생각의 구조화부터"). §8이 그 토대.

## 2. 핵심 설계 원칙 (책 원리 → 아키텍처)

| 책의 인상 깊은 원리 | 아키텍처 결정 |
|---|---|
| **"대화내역보다 폴더 구조"** / 인수인계 문서 계속 갱신 / mermaid 시각화 | 페르소나를 **살아있는 구조화 문서(dossier)**로 관리. 원시 일기·대화 대신 **distill된 문서**를 지속 갱신 → 에이전트 1차 컨텍스트. 프롬프트·eval·의사결정도 폴더로 구조화 |
| **컨텍스트 길어지면 멍청 / 서브에이전트 / 위임 우선** | 분석·생성·채점을 **서브에이전트**로 분리, 메인 대화엔 **압축 dossier**만 주입 |
| **plan→work→review→compound(복리)** | 일기 누적 → 페르소나 풍부 → 개인화↑ → 참여↑ → 데이터↑ = **플라이휠** |
| **HITL→HOTL** | 교정·페르소나 갱신은 자율 실행, 사람은 감독. 전환 기준은 eval로 정량화(§9) |
| **독점데이터·플라이휠·습관화** | 일기+사진은 듀오링고/스픽이 못 가진 **독점 데이터** moat |
| **도메인 지식 우위(리텐션 원리)** | 망각곡선·SRS·소크라테스 교수법을 시스템에 내장(T 역할, §9) |
| **응답속도 0.5초 = 사람처럼** | 즉각 스트리밍 응답 + 경량 모델 라우팅. 추후 음성 확장 |
| **4가지 증강(처리량·시간범위·품질·닫힌 루프)** | 야간 배치로 일기 분석·복습 준비(닫힌 루프) 24/7 |

**한 줄:** LLM은 "분석·생성·대화", 백엔드/DB는 "상태·스케줄", **페르소나 문서는
에이전트의 살아있는 기억**. API 키는 앱에 절대 두지 않는다.

## 3. 목표 & 핵심지표 (KPI / North Star)

- **North Star**: 학습 지속(리텐션) — "어려워도 계속 한다". 예: D7/D30 리텐션,
  주간 활성 학습일, 복습 완료율
- **학습 성과**: 반복 오류 감소율, CEFR 진척, 어휘 정착률(SRS 통과율)
- **에이전트 품질**: 페르소나 정확도(인간 라벨 대비), 소크라테스 룰 준수율
  (정답 즉시 누설 0), 교정 recall/precision
- **운영**: 유저당/세션당 실비용, 캐시 적중률, 응답 지연(p50/p95), 사고(refusal/오류)율

> 구체 목표 수치는 현재 앱 지표(리텐션 등)를 받아 §3에 확정 — **추가 입력 필요**.

## 4. 아키텍처 — 두 개의 평면(plane)

```
                         [모바일 영어일기 앱 (기존)]
                          │ 일기/사진 업로드        │ 대화/학습 요청
                          ▼ (이벤트/배치)           ▼ (실시간 SSE)
┌───────────────────────────────────┐   ┌────────────────────────────────┐
│  ① 비동기 분석 평면 (24/7 자동)     │   │  ② 실시간 대화 평면             │
│  persona-analyzer 서브에이전트      │   │  메인 "외국인 친구" 튜터 에이전트 │
│  - 일기+사진(vision) 분석          │   │  - 페르소나 dossier를 컨텍스트로  │
│  - 페르소나 dossier 갱신           │   │  - 소크라테스식 교정/문답        │
│  - 오류패턴 추출 → SRS 아이템화     │   │  - 맞춤 문제/문장 생성           │
└─────────────┬─────────────────────┘   └──────────────┬─────────────────┘
              │  tool read/write                        │ tool read
              ▼                                         ▼
        [학습 데이터 DB] ──────── 페르소나 dossier(문서) ────────┘
        - 페르소나 문서(persona.md / language_profile.md / error_log)
        - SRS 복습 스케줄(망각곡선) · 일기/사진 원본 · 세션 transcript
                          │ tool calls
                          ▼
                     [Claude API]
```

**왜 두 평면:** 분석은 무겁고 비실시간(야간·이벤트), 대화는 가볍고 실시간. 분석 평면이
만든 **페르소나 dossier가 대화 평면의 연료**(복리 루프).

### Agent SDK는 REST API가 아니다 — 래핑 필요
Agent SDK(Python `claude-agent-sdk` / TS `@anthropic-ai/claude-agent-sdk`)는 세션마다
`claude` 서브프로세스를 띄우고 transcript를 로컬 디스크에 저장 → 모바일 백엔드로 쓰려면:
- **HTTP 래퍼**(Express/FastAPI) + 결과 **SSE** 스트리밍
- user_id → SDK session_id 매핑, 재접속 시 `resume`로 복원
- **SessionStore 어댑터**로 transcript Postgres/Redis 영속화(컨테이너 무상태화)
- 멀티테넌트라 SDK 자동 메모리 OFF(`CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`)

## 5. 페르소나 분석 — 시스템의 중심축 (기능 0)

**추출 차원**(일기 텍스트 + 사진 vision): 관심사·일상·관계·직업 / **성격·말투·유머**
/ 감정·동기 / **CEFR 수준·반복 오류·어휘** / **멘탈모델·사고 깊이** / 사진의 장소·활동·분위기.

**살아있는 페르소나 문서**(폴더 > 대화): `persona.md`(인물 도시에 + mermaid 관계도),
`language_profile.md`(수준·오류·어휘), `error_log`(반복 오류→SRS 자동 등록),
`timeline`(최근 일기 요약). 이 문서들이 1차 컨텍스트, 대화엔 **압축 dossier**만 주입.

**분석 파이프라인(비동기·HOTL):** 일기/사진 수신 → persona-analyzer(vision) →
문서 diff 갱신 → 오류패턴 → SRS 등록 → 복습 스케줄. 야간 배치/업로드 이벤트 트리거.

> 프라이버시: 일기·사진은 민감. 유저별 격리·접근통제·보존정책 필요(§13).

## 6. 도구(tool) 설계

Agent SDK **in-process MCP 서버**로 등록(TS `tool()`+`createSdkMcpServer()`, Python `@tool`).
이름 `mcp__learning__<tool>`, `allowedTools`로 명시 허용.

| 도구 | 역할 | 평면 |
|------|------|------|
| `get_persona(user_id)` | 압축 페르소나 dossier 조회 | ② |
| `update_persona(diff)` | 분석 결과로 문서 갱신 | ① |
| `ingest_journal(entry, photos)` | 신규 일기/사진 수집·분석 트리거 | ① |
| `get_due_items()` | 오늘 복습할 SRS 아이템 | ②/배치 |
| `update_item_review(id, quality)` | 복습 결과로 다음 복습일 계산·저장 | ② |
| `save_generated_item(item)` | 생성 문장/문제 등록 | ② |

- 생성(기능1): `get_persona`→맞춤 생성→**structuredContent**(JSON)로 앱 네이티브 렌더
- 피드백(기능2): 시스템 프롬프트에 친구 페르소나+소크라테스(정답 즉시 X) 인코딩, 멀티턴
- 복습(기능3): **SRS 알고리즘(SM-2/FSRS)은 백엔드 코드**가 계산, LLM은 quality(0~5)만 판정
- **권한 잠금(보안):** Bash/Write/Edit/파일시스템 불필요 → 커스텀 도구로만 한정,
  prompt injection 블래스트 반경 최소화

## 8. LLMOps & 평가 운영 (To-be) — §1 갭을 메운다

현 상태는 "프롬프트 하드코딩 + eval 0 + 실측 비용 0 + 트레이싱 0". 에이전트 전에 토대 구축:

- **프롬프트 레지스트리·버전관리**: 프롬프트를 코드에서 분리, 버전 태깅·diff 추적
  (인수인계 문서처럼 지속 갱신). 현재의 인라인 하드코딩 제거
- **Eval harness + 골든셋**(기능별):
  - 페르소나 분석: 추출 정확도(인간 라벨 대비)
  - 소크라테스: **"정답 즉시 누설 안 함" 룰 채점 + LLM-judge**
  - 교정: 오류 검출 recall/precision · 거짓 교정율
  - 생성: 수준 적합·관심사 반영
- **회귀 테스트 CI 게이트(랄프루프)**: 프롬프트/모델 변경 시 eval 자동 실행,
  기준 미달 머지 차단(테스트·빌드·lint·커버리지 게이트의 LLM판)
- **관측/트레이싱**: 구조화 로그 + 세션/유저ID + 도구 호출 트레이스(OpenTelemetry).
  Agent SDK **Hooks**(Pre/PostToolUse)로 로깅·검증
- **실측 비용**: `usage`·`total_cost_usd` 기반 유저/세션/기능별 집계
  (현 휴리스틱 상수 대체)
- **모델 롤아웃·A/B**: 모델/프롬프트 버전 카나리·A/B, refusal/오류 자동 폴백
- **가드레일**: 프라이버시(일기/사진)·환각·부적절 응답·refusal·입출력 필터
- **공통 인프라 정리**: 중복 `withRetry` → 공통 LLM 클라이언트 유틸(재시도·타임아웃·캐싱 일원화)

## 9. 개발 프로세스 & 역할 (팀이 개발 과정을 공유하는 법)

- **자동화 전환(HITL→HOTL):** 초기엔 사람이 모든 교정·페르소나 갱신 승인(HITL) →
  eval 신뢰 쌓이면 감독만(HOTL). **전환 기준 = eval 통과율·사고율로 정량화**
- **역할(M/T/A):**
  - **M(Supervisor)**: 여러 도메인 넓게 지휘, 우선순위·리스크
  - **T(Expert)**: 교육 도메인 지식(망각곡선·SRS·교수법)으로 워크플로우·eval 설계 —
    **핵심 차별화**(경쟁사는 AI 이전 설계라 못 엎음; 우리는 지금 판을 짠다)
  - **A(Frontline)**: 유저 피드백·정성 신호 수집
- **레포/지식 구조(폴더 > 대화):** 프롬프트·eval·페르소나 스키마·의사결정 로그를
  폴더로 구조화, **mermaid로 파이프라인 시각화**, 인수인계 문서 지속 갱신
- **개발 루프(plan→work→review→compound):** 각 사이클이 eval·프롬프트·페르소나 자산을
  누적 → 다음이 쉬워짐(복리)
- **의사결정 로그(ADR):** 모델·SRS 알고리즘·프라이버시 결정 기록

## 10. 프롬프트 캐싱 · 비용

- 큰 **시스템 프롬프트**(친구 페르소나+소크라테스 가이드+출력 포맷)는 안정 → 캐싱
  (`systemPrompt`). 캐시 읽기 ~0.1배
- **유저별 페르소나는 도구 결과로** 주입(캐시 프리픽스 뒤). 날짜·관심사·세션ID를
  시스템 프롬프트 앞에 넣으면 캐시 깨짐(silent invalidator)
- 효과는 활성 사용자 규모에 비례. 실측 비용은 §8로 추적

## 11. 동기 설계 — "계속 학습하게"

- **깊은 개인화**(페르소나) → 친구가 내 삶을 안다 → 정서적 유대·습관화
- **소크라테스식** → 떠먹여주지 않아 성취감, 좌절 대신 자기 발견
- **망각곡선 복습** → 잊기 직전 복습 → 정착·진전 체감
- 시스템 프롬프트에 **격려 톤 + 적응형 난이도**(어려우면 단계 낮춤) 인코딩
- "0.5초 응답" → 즉각 스트리밍으로 사람 같은 친구 경험

## 13. 리스크 & 추가 결정 필요
- **언어/런타임**: TS(Node 18+) vs Python(3.10+) — 기존 백엔드 스택에 맞춤
- **OpenAI→Claude 마이그레이션 범위·일정** (현 파이프라인 영향)
- **페르소나 저장 형태**: 마크다운 문서 vs 구조화 DB vs **하이브리드(추천)**
- **SRS 알고리즘**: SM-2(단순) vs FSRS(정밀)
- **프라이버시/보존**: 일기·사진 분석 동의 범위, 페르소나 격리·삭제 정책
- **실시간 UX**: SSE vs WebSocket, 추후 음성(0.5초)
- **Agent SDK vs Claude API 직접**: 운영 부담 재검토
- **현재 앱 지표** 공유 필요 → §3 목표 수치 확정
