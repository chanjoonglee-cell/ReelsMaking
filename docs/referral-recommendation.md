## 0. 결론 먼저 (TL;DR)

언어의숲 레퍼럴의 **단 하나의 핵심 명제**:

> **"릴스 영상"이 우리의 드롭박스 스토리지다.** 공유 본능을 자극하는 제품 결과물 자체를 바이럴 엔진으로 쓰고, 보상은 현금이 아니라 *제품(구독·크레딧)*으로, 공유는 *별도 화면이 아니라 릴스 만드는 흐름 안*에 박아 넣는다.

권고하는 설계 한 장 요약:

| 구분 | 권고 |
|------|------|
| 보상 형태 | **제품형**(구독 기간 / 릴스 크레딧). 현금·기프티콘 ❌ |
| 보상 구조 | **양방향**(추천인+피추천인 모두) |
| 보상 타이밍 | 가입 → *즉시 작은 해제* / 첫 결제 → *양방향 큰 보상* |
| 공유 트리거 | **릴스 저장/완성 기능 잠금** (별도 "친구 초대" 화면 ❌) |
| 받는 사람 후킹 | 초대 링크가 아니라 **"○○가 만든 영어 일기 영상"** |
| 반복 유발 | **주간 일기 스트릭** + near-miss("조금만 더 하면") |
| 출시 | Crawl → Walk → Run 3단계 |

---

## 1. 핵심 통찰 — 왜 "릴스 = 드롭박스 스토리지"인가

레퍼럴 역사상 두 갈래가 있다:

- **PayPal**: 현금 $20 + $20. 효과는 있었지만 **$60M 소진** — 비싸고, "돈 노리는 유저"를 끌어들임
- **드롭박스**: 현금 대신 **저장공간(제품)** 양방향 500MB. 15개월 **3900% 성장**.
  → 인프라 비용은 천천히 늘어 **비용이 스케일하지 않음**, 그리고 *"제품을 원하는 사람"만 self-select* 되어 좋은 유저가 들어옴

**언어의숲의 결정적 자산**: 토스는 공유할 거리(동그라미)·기대감(복권)을 *발명*해야 했지만, 우리는 이미 **자랑하고 싶은 릴스 영상**을 만든다. 이게 드롭박스의 스토리지처럼:
- 공유 본능을 자극하는 **제품 결과물**이고
- 친구에게 가면 그 자체가 **콘텐츠(기대감)** 이며
- 워터마크+링크를 실어 **스스로 퍼지는 매개체**가 된다

→ 따라서 우리 레퍼럴은 "초대하면 OOO 드림" 식 캠페인이 아니라, **릴스 제작·공유 흐름 자체**여야 한다.

## 2. 보상 설계 — 무엇을, 누구에게, 언제

### 2.1 무엇을 → 제품형 보상 (현금 금지)
드롭박스 교훈 그대로. 언어의숲은 **구독 기간 연장 / 릴스 제작 크레딧 / 프리미엄 기능 해제**로 보상한다.
- 비용이 매출처럼 빠르게 늘지 않음 (무료 기간 = 한계비용 낮음)
- 영어 학습을 *진짜 원하는* 유저가 들어옴 (현금 보상은 어뷰저를 부름)
- 무료 기간 = 학습 시간 ↑ → **습관 형성**(언어 학습의 핵심) → 리텐션 ↑

### 2.2 누구에게 → 양방향 (SaaS의 78%가 채택)
듀오링고("둘 다 1주 무료"), 드롭박스("둘 다 500MB") 모두 양방향. 단, **"내가 받는다"가 아니라 "친구에게 선물한다"** 프레이밍이 전환율을 높임.
- 피추천인: 가입 시 **연장된 무료 체험**(예: 프리미엄 14일) → 진입 마찰 ↓
- 추천인: 아래 타이밍 참고

### 2.3 언제 → 2단 지급 (어뷰징 방어의 핵심)
리서치 공통 결론: **가입만으로 큰 보상을 주면 어뷰징이 폭발**한다. 의미 있는 행동(첫 결제, 쿨링오프 경과) 후 지급해야 함.

| 시점 | 트리거 | 보상 |
|------|--------|------|
| **1차 (즉시 보람)** | 피추천인 가입 + 첫 릴스 생성 | 추천인 *워터마크 제거 / 릴스 크레딧 +N* |
| **2차 (자격 충족)** | 피추천인 **첫 유료 결제** (환불기간 경과) | 추천인·피추천인 **양방향 구독 1개월** |

→ 빠른 보람(1차)으로 동기를 살리고, 진짜 보상(2차)은 매출이 발생한 뒤에 준다.

## 3. 세 레버 실행안 (토스 K 공식에 매핑)

> **K = 공유 시도율 × 공유 성공률 × 인당 초대자 수**

### 레버 ① 공유 시도율 → '명분' = 릴스 기능 잠금
토스 동그라미 챌린지 구조. **별도 "친구 초대" 메뉴를 만들지 않는다.**
- 릴스 생성·미리보기는 **항상 무료** (먼저 "와" 하는 성공 경험 — 토스도 동그라미를 *먼저* 그리게 함)
- 워터마크 없이 저장 / 더 멋지게 완성 → **친구 초대로 해제**
- 즉, 공유가 보상이 아니라 *"내 영상을 소장하기 위한 수단"* 이 됨
- 듀오링고 데이터: **성취 배지 공유 → 레퍼럴 116% 증가**. 릴스 완성 화면에 "이 영상 자랑하기 + 친구도 만들게 하기"를 자연스럽게 배치

### 레버 ② 공유 성공률 → '기대감 + 즉시성'
- 친구가 받는 것 = 초대 링크 ❌ → **"○○가 만든 영어 일기 영상"** ✅ (안 열 수 없음)
- 들어오면 **즉시** "너도 네 사진으로 1편 무료로" → 가입 *전에* 가치 체험 (복권의 즉시성)
- 무료 공유 영상의 워터마크 = 브랜드+링크를 친구 피드로 나르는 매개체 (누수가 아니라 채널)

### 레버 ③ 인당 초대자 수 → '반복하고 싶은 아쉬움' ★ 가장 어려움
토스 교훈: **보상을 늘리는 1차원적 접근으론 반복 공유가 안 됨.** "조금만 더 하면 되겠는데?"(near-miss)를 설계해야 함.

언어의숲 권고 — **주간 영어 일기 스트릭**을 메인 반복 엔진으로:
- 매주 일기 N편 → 릴스 자동 생성 (듀오링고 스트릭 = 언어 앱의 검증된 반복 장치)
- 스트릭이 **아쉽게 끊길 위기** → 친구 초대로 "스트릭 프리즈/복구"
- 보조: 발음·표현 점수 챌린지("한 끗 차이로 만점 놓침 → 재도전은 공유")
- 듀오링고식 **성취 배지/리더보드** 얹어 친구와 비교 → 공유 동기 추가

## 4. 어뷰징 방어 (요지)
리서치 공통 위험신호 기반:
- **신규 유저만** 피추천인 자격 / **자기 초대 차단**(동일 기기·결제수단·IP 군집)
- **큰 보상은 첫 결제 + 환불기간 경과 후** 지급 (review window)
- 한 추천인에서 **가입 급증, 데이터센터 IP/VPN, 낮은 사용시간** → 플래그
- 추천인 **보상 상한**(예: 연 최대 12개월치)

---

## 5. 측정 — K를 항별로 본다
| 레버 | 봐야 할 지표 |
|------|------------|
| 공유 시도율 | 게이트 노출 → 공유 클릭 전환율 |
| 공유 성공률 | 링크 열람률, 가입 전환율 |
| 인당 초대자 수 | 추천인당 자격충족(첫 결제) 친구 수 |
| 종합 | **K = 세 항의 곱** (목표: K → 0.5+ 부터, 궁극 1.0 지향) |

퍼널: `릴스 생성 → 저장 게이트 노출 → 공유 → 링크 열람 → 가입 → 첫 릴스 → 첫 결제`
(분석 인프라로 Mixpanel 연동되어 있어 그대로 이벤트 설계 가능)

## 6. 단계적 출시 (Crawl → Walk → Run)
복잡하게 한 번에 만들지 말고 K를 보며 키운다. SaaS 교훈: **"하나의 명확한 제안, 하나의 행동, 30초 안에 공유"**.

- **Crawl** — 양방향 제품형 보상 + 릴스 저장 기능 잠금(레버①)만. K 베이스라인 측정
- **Walk** — 받는 사람 기대감/즉시성(레버②) 강화: 영상 미리보기 딥링크, 즉시 무료 체험
- **Run** — 반복 엔진(레버③): 스트릭·배지·챌린지로 인당 초대자 수 공략 ← 여기가 K를 1.0 너머로 밀어 올리는 구간

---

## 7. 지금 결정해야 할 것 (전략 레벨)
1. **반복 엔진(레버③)** — 주간 스트릭 / 점수 챌린지 / 릴스 완성도 중 메인은? (권고: 스트릭)
2. **보상 크기** — 구독 며칠 / 크레딧 몇 개? (권고: 피추천인 14일 체험, 양방향 1개월)
3. **기능 잠금 강도** — 워터마크 제거만 vs 2번째 릴스부터 (A/B 권장)
4. **딥링크 인프라** — Branch.io / AppsFlyer / 자체 (Firebase Dynamic Links는 2025 종료)
