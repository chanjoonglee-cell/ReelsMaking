# 자기참조형 인출 기반 학습 AI Agent — 설계문서

> **포지셔닝**: 「자기참조형 인출 기반 학습」 — 개인화 언어학습 AI Agent (언어의숲)
> **용도**: 내부 설계 + PoC("Solar 기반 소크라틱 학습 AI 튜터") 제안서 와꾸
> **상태**: v1 (우리 가설). 세미나 녹음(260616) 오버레이 예정. PoC 접수 = 수요일.
> **작성 원칙(멘토 반영)**: 솔루션이 아니라 **목표 → 제약 → 평가 → 후보 비교 → 선택** 순서.

# 0. 한 장 요약 (Executive Summary)

- **무엇**: 유저의 일기·사진(=나의 이야기)으로, *내 생각을 외국어로 표현(인출)* 하게 만드는 개인화 학습 에이전트.
- **왜 에이전트**: "이 학습자에게 지금 무엇을 연습시킬까(target selection)"는 누적 상태에 따라 갈려 코드로 못 적음 → 에이전트가 필요한 *유일하고 진짜인* 지점.
- **차별점**: 외적보상 없이 **인출+자기참조+몰입**으로 내적동기 유발 → persistence(작심삼일→작심칠일).
- **검증**: "되는지 뭘로 판단?"의 **평가 기준**을 먼저 세우고, 기억/개인화 **솔루션 후보를 테스트**해 선택. 피칭은 *돌아가는 데모*로.

# 1부. 배경 & 개념 — 왜 에이전트인가

## 1.1 에이전트란 무엇인가
- **정의**: 환경을 인지→판단→행동하는 자율 루프. LLM 시대엔 **LLM이 제어흐름(다음 행동)을 스스로 결정**.
- **개념 vs 마케팅**: "agent"는 경제학·AI(러셀&노빅, 1995)의 정통 개념. 단 LLM 붐 이후 남발됨 → 우리는 *테스트 가능한* 정의를 씀.
- **6요소**: ①목표 ②인지(perception) ③기억(memory) ④계획(planning) ⑤도구(tools) ⑥성찰(reflection). *③기억·⑥성찰이 L1↔L2를 가르는 기둥.*
- **워크플로우 vs 에이전트**: 같은 부품(LLM+도구)이라도 **경로를 코드가 정하면 워크플로우, 모델이 정하면 에이전트.**
- **성숙도 사다리**: L0 단일호출 / **L1 LLMOps(경로 고정) ← 현 위치** / **L2 에이전트(동적 결정) ← 목표** / L3 다중 에이전트.

## 1.2 학습 에이전트 & 그 필요성
- **학습의 이중성**: A.가르치는 학습(사용자를 학습) + B.배우는 학습(사용자에 대해 학습). **둘 다 있어야** 학습 에이전트. (B가 LLMOps를 넘는 지점)
- **"학습에 에이전트가 꼭 필요한가?" 판별 테스트**:
  > 다음 행동을 *모든 학습자 공통 순서도*로 그릴 수 있나? → **가능하면 워크플로우(과설계 금지), 불가능하면 에이전트.**
  - 불필요: 고정 커리큘럼, 단발 작업 → 워크플로우/단일호출로 충분.
  - 필요: 열린 진단, 적응형 경로, 장기 개인화 → 에이전트.
- **핵심 결정 = target selection**: *"누적 상태를 보고 이번에 무엇을 연습시킬까."* 나머지(생성·피드백)는 이를 실행하는 도구.

## 1.3 우리의 관점 — 「자기참조형 인출 기반 학습」

### 학습이론 기반
- 학습 = **학(습득)** + **습(인출/산출)**. 기억은 *인출 과정*에서 남음.
- 문제: 인출은 에너지 비용이 큼 → 이탈. 모바일은 집중력↓. → **persistence 유지가 핵심 과제.**
- 해법: **자기관련 정보**(내 일기)로 정보효율↑ + 인지부하↓, 동시에 **인출(speaking/writing)을 유지**.
- SLA 풀스택: 출력가설(Swain) · 자기참조 효과 · 인출연습 · **변주(variation/전이)** · 몰입(i+1) · 간격반복.

### 동기 설계 — 외적보상 배제
- **철학: 외적 토큰(점수·뱃지·코인) 전면 배제.** 순수 내적동기 — *문장을 만들고 맞추는 쾌감*으로 스스로 유입. (SDT: 외적보상은 내적동기를 밀어냄)
- **퍼즐 가설 = 몰입(Flow)**: 언어학습 = 퍼즐(문법=규칙, 단어=조각). *난이도 ≈ 실력* = 몰입 = **i+1**. 직관(퍼즐의 재미)과 학습과학(적정 난이도)이 같은 것.
- **효과↔지속 수렴**: 몰입 지점에서 *학습 효과*와 *지속*이 같은 점에서 만남. 외적보상 없이 "스스로 유입"되는 메커니즘.

### ★ 데이터 기여 → 보상 원칙 (B안)
> 유저가 데이터(일기·사진)를 넣을수록 보상받는 느낌은 옳다. **단, 토큰이 아니라 "경험/개인화가 나아짐" 이어야 한다.**

| 구분 | 예 | 판정 |
|---|---|---|
| A. 외적 토큰(통제적 보상) | 데이터 N개 → 포인트·뱃지 | ❌ 철학 위반 + **데이터 덤핑(오염)** 유발 |
| **B. 경험이 나아짐(정보적 보상)** | 넣을수록 *더 나를 알아주고 나다운* 연습 | ✅ 채택 |

- **SDT 핵심 선**: *정보적 보상(competence를 알려줌)* O / *통제적 보상(토큰 미끼)* X.
- **구체 형태**: ①개인화 체감("어제 그 카페…" 내 데이터가 살아 돌아옴) ②성장 시각화(언어의**숲**이 자람 — *진짜 숙련/기록의 반영*, 장식 X) ③숙련 지도 채워짐.
- **★ 플라이휠을 *보이게***: `데이터↑ → 모델이 나를 더 앎 → 경험이 더 나다워짐 → 더 넣고 싶어짐 ↺`. 이 루프를 *체감*시키는 것 = "넣을수록 보상" + 철학 유지 + persistence 직격.
- 한 줄: **보상하지 말고, 나아짐을 보여줘라.**

### 북극성 — "AI가 인간을 강화학습한다"
- 주체 반전 RL: **인간=학습되는 정책, AI=환경+보상(내적)**. Goal=체화(자동화). AI=**몰입 설계자**(보상 분배기 X).
- 진화 축: **반응형 → 능동형**. 궁극엔 유저 입력 없이 AI가 먼저 말 검.

# 2부. 목표 & 제약 & 성공기준 (← 솔루션보다 먼저)

## 2.1 목표
1. **개인화**: 나와 관련된 소재로, 내 약점을 노린 연습.
2. **일관성(persistence/기억)**: 과거를 계속 들고 매 대화에 반영. "나도 몰랐던 걸 상기시켜 줌."
3. **체화(자동화)**: 통제적 처리 → 자동적 처리. (대량 반복 × 긴 시간 = 습관 전제)

## 2.2 제약사항 (Constraints)
- **레이턴시**: 즉각성이 생명("말로 하는 테니스"). 현재 피드백 ~8초 → **단축 필수.**
- **모바일**: 집중력↓ → 저마찰·짧은 인터랙션(하루 5분).
- **Solar LLM 기반**(PoC 요구) → **모델 추상화 레이어** 필요(현 GPT-4o).
- **인출 비용 → 이탈**: persistence 설계가 곧 제품 생사.

## 2.3 ★ 성공의 정의 = 평가 기준(Eval) (← 멘토 1순위)
> "working 하는지 *뭘 갖고* 판단?" — 지금 근거 없음(정성 느낌뿐). **평가 조건부터 정의.**
- **2층 평가**:
  1. **컴포넌트 품질**: 생성 영어가 정확/자연한가, 피드백이 정확한가, 소크라틱 발문이 적절한가. (오프라인 eval + 골든셋)
  2. **에이전트 결정 효과**: target selection이 실제로 학습·persistence를 올렸는가. (온라인 메트릭)
- 이 평가축이 있어야 **솔루션 후보 선택(4부)** 이 가능. PromptOps가 존재하는 이유.

# 3부. 시스템 설계 — 무엇을 만드나

## 3.1 학습자 모델 (정통: ITS의 Student Model / Knowledge Tracing)
**3 얼굴**:
| 얼굴 | 담는 것 | 쓰임 |
|---|---|---|
| 학습 모델 | 실력선, 문법/어휘 숙련도, 약점·오개념, 망각곡선 | target selection, 몰입 난이도, 변주 정도, 복습 |
| 삶 모델 | 관심사, 최근 사건, 반복 인물/장소 | 개인화 콘텐츠, 능동 말걸기 |
| 습관 모델 | 스트릭, 접속 시간대 | persistence, 능동 타이밍 |
- **숙련도 = 연속/누적값**("몇 가지 변형까지 성공했나") — 변주·몰입 난이도가 읽는 신호.
- **미해결**: 숙련도 표현(연속+변형카운트 추천) / 추적 단위(문법구문? CEFR?) / 콜드스타트(관심사 선택=삶 콜드스타트, 학습 콜드스타트는 별도).

## 3.2 행동·도구 (Action Space)
**0. ⭐ 오케스트레이터(정책) = 에이전트의 정체**: 학습자 모델을 읽고 *무엇·난이도·변주·소크라틱vs quick-fix·복습*을 결정 → 도구 호출 → 결과로 모델 갱신.
**도구(손발)**:
| # | 도구 | 보정 |
|---|---|---|
| 1 | 데이터 분석 + 한국어 프롬프트 생성 | 분석(인지)과 생성(실행) 분리 |
| 2 | 페르소나 설정·업데이트 → 기억 | 삶+학습 둘 다. 저장방식=후보 비교(4.2) |
| 3 | 영어 문장 생성 | 그라운딩(할루 방지) + **복수 정답 허용** |
| 4 | 피드백 + 소크라틱 발문 | dosed(선택적). 오개념 진단 전제 |
| 5 | 자동복습 타이밍·제안 | **결정론적 SRS**(SM-2/FSRS)로 간격, 에이전트는 *언제*만 |
| #1 | **답안 평가·채점** | STT+의미 동치+오류 검출+발음 (모든 신호의 출처) |
| #2 | 콜드스타트 진단 | 배치/첫 일기 추정 |
| #3 | 숙련도 추정(KT) | 정량 — 몰입 난이도 연료 |
| #4 | 안전·프라이버시 | 일기=민감정보. PII·콘텐츠안전·위기감지 |
| #5 | 에이전트 자기평가 | = 2.3 평가, 운영 관측 |

## 3.3 에이전트 루프
```
인지(분석·채점) → 계획(오케스트레이터: target·난이도·변주·복습) → 실행(생성·피드백/소크라틱) → 성찰(모델·전략 갱신)
```

## 3.4 현재 제품 매핑 (Figma)
- 확인된 루프(=Stage 1): 기록(일기+사진) → 표현 생성 → **PracticeSpeaking(말하기)** → Speaking-Score → 피드백 → Done. *음성 산출 = 인출형 ✅*
- **에이전트 진입점 = StudySettings**(현재 Level/Count/Type 수동 → 에이전트 자동 보정, 수동은 오버라이드).
- 콜드스타트: **관심사 선택** 화면 / 인벤토리: 단어장·나의표현·스크랩 / 신호: Speaking-Score·Mixpanel.
- Stage 3(능동형)은 아직 디자인에 없음.

# 4부. 솔루션 탐색 & 검증 (← 후보→테스트→선택)

## 4.1 핵심 설계 질문 (솔루션을 목표·제약으로 환원)
- "기억/개인화를 어떻게 구현?" → **목표(개인화+일관성) + 제약(레이턴시·Solar)** 으로 환원 후 후보 비교.
- "RAG 써야 할 것 같은데"는 *솔루션 먼저*의 함정. RAG는 후보 중 하나.

## 4.2 솔루션 후보 비교 (기억·개인화)
| 후보 | 강점 | 메모 |
|---|---|---|
| RAG(벡터 검색) | 대용량 검색 | 청킹/관련성 튜닝, 상반기 시도했으나 정체+*측정 불가* |
| 바닐라 문서 주입 | 단순 | 소규모/저빈도엔 충분 |
| MD 계층 + 청킹 | 검색 없이 효율 가능 | 하이라키 잘 나누면 충분(멘토 추천 비교군) |
| 롱컨텍스트 | 그냥 다 주입 | 컨텍스트 커진 요즘 유효 |
- **선택 원칙**: 평가 기준(2.3)으로 후보 테스트 → 최적 선택. ("넣었다 별로면 버리기" ❌)

## 4.3 평가 기반 선택법
- 골든셋 + 평가 지표(정확/자연/관련성/레이턴시)로 후보별 A/B 테스트 → 근거로 아키텍처 확정.

## 4.4 오픈 퀘스천 (멘토·세미나와 논의)
- 기억 구현 후보 중 무엇을, 어떤 평가로?
- "working"의 정량 정의 / 레이턴시 목표치(예: <2초)와 품질 트레이드오프.
- 추적 단위 / **번역 vs 직접 사고**(한→영 구조) / **닫힌 퍼즐 vs 열린 소통**.

# 5부. 실행

## 5.1 단계별 로드맵
| | S1 (워크플로우+계측) | S2 (개인화 두뇌 = PoC) | S3 (능동형) |
|---|---|---|---|
| 핵심 | LLMOps 루프 + **계측** + **답안채점** + **안전** | 오케스트레이터 + 학습자모델 + KT + 변주 + 소크라틱 + 기억(후보선택) | 먼저 말걸기 + 이탈 감지 |
| 게이트 | — | 학습자 모델 추정 가능 | 관련 *할 말* + 신뢰 |
- **★ Stage 1.5 계측**: 정답/오답·반응시간·오류유형·회피 로깅 — *지금 가장 싼 핵심 투자*(없으면 S2 재료 0).
- 빌드 오더: 계측 → S2(a.모델+진단 → b.난이도자동화 → c.변주 → d.소크라틱+기억) → S3.

## 5.2 PoC 범위 & 데모 계획
- 범위: a/b(학습자모델+진단+난이도) 중심으로 *돌아가는 플로우*.
- 데모: 후보 테스트 결과 + "왜 이건/저건" + 동작 시연. (단순 "RAG 썼습니다" ❌)

## 5.3 타임라인
- 이번 주: 와꾸(본 문서) + 후보 서치 + 평가 기준. **수요일 접수.**

# 부록 A. 리스크 & 검증 항목
1. ⚠️ 번역 ≠ 직접 사고 (한→영 구조) — 세미나 1순위.
2. ⚠️ 닫힌 퍼즐(정답1개) ≠ 열린 소통 → 복수 정답/부분점수.
3. 외적보상 → 내적동기 잠식 (B안으로 해소: 정보적 보상).
4. 능동 말걸기 → 알림 피로 (말 걸 권리를 데이터로 벌기).
5. 레이턴시(8초) → 인터랙션 붕괴.
6. RAG 조기 확정(솔루션 우선) → 평가 기반 선택으로 교정.
7. ⚠️ **동기 0→1 한계**: AI는 동기를 *증폭(곱하기)*하지 *생성(덧셈)*은 못함(세미나 합의). AI-only 대중 매스의 구조적 구멍. → 답: 과정의 재미(몰입) + 인정(B보상=전문가 "칭찬") + 관계성/커뮤니티.
8. ⚠️ **실력 격차 확대**(오혜연): 초보·저동기 유저는 질문조차 못 만들어 더 뒤처짐 → 이탈. → 콜드스타트 + 비계(scaffolding)가 생존 기능.
9. **속도↔성찰 긴장**(이성환): 너무 빠른 인터랙션은 메타인지/성찰을 죽이고 편향 증폭. → 소크라틱 발문으로 성찰 주입.
10. **평가 순환**: AI가 만든 걸 AI가 평가하는 모순(LLM-judge) → 샘플링 + 휴먼 체크 + process 평가.

# 부록 C. 세미나 오버레이 (260616 KAIST 학습에이전트 세미나)

## C.1 🟢 수렴 (전문가가 우리 설계 확인)
| 우리 설계 | 세미나 근거 |
|---|---|
| 소크라틱·비계 피드백 | 이태우: 2-시그마(Bloom)·하버드 물리 AI튜터·Khan — "정답 한번에 X, step-by-step, 학생이 먼저 시도, 단계별 힌트" |
| 관심사 기반 개인화 | 오혜연: 지문을 야구/주식/환경으로 — "personalization은 AI가 잘함" |
| 기억·일관성 + 할루 방지 | 이성환: **"환각 + 길게 기억 못함"이 핵심 약점** |
| 오케스트레이터 + 목표/제약/평가 | 이재길: 가치문제 정의 → 목표·맥락·데이터·도구·제약·평가기준 명확화 → 실행 지휘 → 검증 |
| 체화(automatization) | 이성환: "embodiment, AI 없이 직접 풀어봐야", "토큰=내 몸값 당겨쓰기" |
| 외적보상 배제·과정의 재미 | (발표자 본인 마무리) "결과 가치 말고 *과정의 즐거움*을 찾으라" |

## C.2 ⚠️ 반영 diff (신규 통찰)
1. **동기 0→1 한계**: AI는 동기를 곱하기(증폭)만, 덧셈(생성)은 못함. 핵심 레버 = 칭찬/인정(이태우) + "왜 배우는가" 의미·관계(좌장). → 우리 답: 몰입(과정 재미) + **B 정보적 보상 = "칭찬"의 AI 버전** + (신규)관계성/커뮤니티. [리스크 7]
2. **AI가 실력 격차 확대**(오혜연): 초보는 질문조차 못 만들어 더 뒤처짐 → 콜드스타트+비계 = 대중 매스 생존 기능. [리스크 8]
3. **속도↔성찰 긴장**(이성환): 빠른 인터랙션 = 메타인지 못 거름 → 소크라틱으로 성찰 주입. [리스크 9]
4. **평가 순환**(오혜연·이태우): LLM-judge 모순 → 샘플링+휴먼+process 평가. [리스크 10]
5. **메타인지 지원**(이성환): "내가 뭘 알고 모르는지" 자각 = 학습자에게도 길러줄 대상 → 학습자 모델 가시화(숙련 지도)와 연결.

## C.3 전략 takeaway
> 메커니즘(소크라틱·개인화·기억·체화·과정의 재미)은 전문가 검증 통과.
> **남은 진짜 과제 = 동기 0→1 + 격차** (AI-only 대중 매스의 구조적 한계). 답 = 몰입 + 인정(B) + 비계·관계성.
