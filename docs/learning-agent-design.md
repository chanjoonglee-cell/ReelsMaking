# 1장. 정의

## 1.1 에이전트란 무엇인가

### 고전적 정의 (AI 일반)
> **에이전트(Agent)** = 환경을 **인지(perceive)** 하고, 목표를 달성하기 위해 그 환경에 **자율적으로 행동(act)** 하는 시스템.
> — 인지→판단→행동의 루프를 *스스로* 돈다는 점이 핵심 (Russell & Norvig).

### LLM 시대의 재정의
LLM 에이전트는 **LLM을 추론 엔진(reasoning engine)으로 삼아, 자신의 제어 흐름(control flow)을 스스로 결정**하는 시스템이다. 즉 "다음에 무엇을 할지"를 코드의 `if/else`가 아니라 모델의 판단이 정한다.

### 에이전트 판별 기준 (4가지)
무언가가 "에이전트인가?"를 가르는 질문들:

| 기준 | 질문 | 에이전트라면 |
|---|---|---|
| **① 자율성** | 다음 행동을 누가 정하나? | **모델이 동적으로** 결정 (코드가 아님) |
| **② 목표지향** | 무엇을 향해 움직이나? | 명시된 목표 상태로 수렴 |
| **③ 상태/기억** | 과거를 기억하나? | 세션·장기 메모리 보유 |
| **④ 도구·환경** | 외부에 영향을 주나? | 도구 호출로 환경과 상호작용 |

### 에이전트가 *아닌* 것 (대조)

| 형태 | 왜 에이전트가 아닌가 |
|---|---|
| 단일 LLM 호출 | 무상태, 자율성·목표 없음 (입력→출력 1회) |
| 자동화/RPA·스크립트 | 흐름이 완전 고정, 판단 없음 |
| **워크플로우(LLM 파이프라인)** | LLM·도구를 쓰지만 **경로가 코드로 미리 정해짐** |
| 일반 챗봇 | 반응형 대화, 목표·계획·자기수정 없음 |

> **워크플로우 vs 에이전트** — 같은 부품(LLM+도구)을 써도, *경로를 코드가 정하면 워크플로우, 모델이 정하면 에이전트*. 이것이 우리가 가려는 **L1(LLMOps) → L2(Agent)** 의 본질.

### 성숙도 사다리 (현재 위치)

| 단계 | 특징 | 다음 행동 결정자 |
|---|---|---|
| L0 단일 호출 | 무상태 | 사람(프롬프트) |
| **L1 LLMOps 파이프라인** | 체이닝·관측·평가, **경로 고정** | 개발자(코드) ← *현재 우리 위치* |
| **L2 에이전트** | 상태+도구+**동적 행동 결정** | 에이전트 자신 ← *목표* |
| L3 다중 에이전트 | 역할 분담·위임 | 오케스트레이터 |

## 1.2 학습 에이전트란 무엇인가

위 일반 에이전트 정의를 **학습 도메인**에 투영한다.

| 일반 에이전트 | → 학습 에이전트 |
|---|---|
| 환경(environment) | **학습자**(그의 지식 상태·반응) |
| 목표(goal) | 학습자를 현재 수준 → 목표 역량으로 이동 |
| 인지(perceive) | 답변·발화·오답·반응시간을 **진단**으로 해석 |
| 행동(act) | 교수 활동(입력 제시·연습·교정·복습) 선택·실행 |

### 핵심: "학습"의 이중성
이 도메인에서 'learning'은 두 방향을 동시에 의미하며, **둘 다 있어야** 학습 에이전트다.

| | A. 가르치는 학습 (Teaching) | B. 배우는 학습 (Adaptation) |
|---|---|---|
| 주체 | 에이전트가 **사용자를** 학습시킴 | 에이전트가 **사용자에 대해** 학습함 |
| 산출 | 다음 학습 활동 | 갱신된 학습자 모델·전략 |
| 빠지면 | 개인화 없는 추천기 | 매번 리셋되는 정적 튜터봇 |

> **A↔B 두 루프가 맞물려 도는 것** = LLMOps를 넘어서는 결정적 지점. (대부분의 "AI 튜터"는 A만 있고 B가 없다.)

### 한 문장 정의
> **학습 에이전트** = 영속적 **학습자 모델**을 들고, 매 턴 학습자 신호를 **진단**해, 학습과학 원리를 행동 선택지로 삼아 **다음 학습 활동을 스스로 계획·실행**하고, 그 결과로 **학습자 모델과 전략을 갱신**하는 폐루프 시스템.

### 학습 에이전트 판별 기준 (4기준의 학습 도메인 투영)

| 기준 | 학습 에이전트에서 |
|---|---|
| ① 자율성 | "지금은 새 입력? 연습? 복습? 교정?"을 **스스로** 선택 |
| ② 목표지향 | ZPD/*i+1* 기준 목표 역량으로 수렴 |
| ③ 상태/기억 | **학습자 모델**(약점·이력·망각곡선) |
| ④ 도구·환경 | 콘텐츠 생성·채점·SRS 스케줄러·자료검색(RAG) |

### 학습 에이전트가 *아닌* 것
- **정적 튜터 챗봇**: 매 세션 리셋, 학습자 모델 없음 (B 결여)
- **문제 추천 시스템**: 개인화는 하나 교수 루프·자기수정 없음 (A 결여)
- **LLMOps 콘텐츠 생성 파이프라인**: 경로 고정, 동적 행동 결정 없음 (현재 우리 위치)

### 우리가 만들 것 (범위)
**언어학습 메커니즘을 코어로 하는 범용 학습 에이전트.** 언어학습의 검증된 원리(이해가능한 입력·출력강제·인출연습·간격반복·비계설정)를 **행동 선택지(action space)** 로 삼되, 구조 자체는 타 과목으로 일반화 가능하게 설계.

# 1.5장. 우리 제품 정의

## 1.5.1 문제 정의
> 언어학습 = **내 생각을 외국어로 표현하는 것**. 따라서 **"나의 이야기"로** 공부해야 한다.

- "나의 이야기"를 받는 1차 수단 = **일기(텍스트+사진)** *(다른 방법도 가능)*
- **하루 5분, 꾸준히** — 저마찰 습관형 마이크로러닝

## 1.5.2 현재 플로우 (Stage 1 = 워크플로우)
1. 유저가 일기(텍스트·사진)를 쓴다
2. LLMOps가 내용 분석 → 한국어 문장 1~5개 생성
3. 한국어 문장 제시 → 유저가 **영어로 표현(production)**
4. **즉각 피드백**
5. (일상·학습 데이터 누적 → 점점 맞춤형) ← *여기가 에이전트의 자리*

## 1.5.3 학습과학 근거 (왜 이 설계가 유효한가)
| 우리 설계 | 검증된 원리 |
|---|---|
| 내 생각을 외국어로 "표현" | **출력 가설(Swain Output Hypothesis)** |
| "내 이야기"로 공부 | **자기참조 효과(self-reference effect)** |
| 한국어→영어 산출 | **강제 출력(pushed output)** / 인출 연습 |
| 즉각 피드백 | 형성 평가 + 교정 피드백 |
| 데이터 누적 → 맞춤형 | 적응형 학습 = **B루프(배우는 학습)** |

## 1.5.4 북극성 컨셉 — "AI가 인간을 강화학습한다"
주체를 뒤집은 RL: **인간이 학습되는 정책, AI가 환경+보상**.

| RL 요소 | 우리 앱 |
|---|---|
| Agent(학습 주체) | **인간(유저)** |
| Policy | 유저의 "외국어로 사고하는 습관" |
| Environment + Reward | **우리 AI** (문장 제시·피드백) |
| Goal | **체화·자동화** (통제적 처리 → 자동적 처리) |
| Curriculum | target selection (다음에 뭘 연습?) |

> **학습 에이전트의 정체 = 인간을 훈련시키는 "트레이너 겸 환경".** 일 = *체화*를 향해 커리큘럼·보상을 설계 (= 최적 교수 정책).

## 1.5.5 Why Agent — 에이전트의 존재 이유
**핵심 결정 = target selection**: *"이 학습자의 누적 상태를 보고, 이번에 무엇을 연습시킬 것인가."*
나머지(문장 생성·피드백)는 이 결정을 실행하는 **도구**. 두뇌만 에이전트, 손발은 워크플로우.

- ①~④단계 = 워크플로우 (고정 경로, 그대로 둠)
- "점점 맞춤형" = 에이전트 (코드로 못 적는 개인화 의사결정)
- 판별 테스트: *"다음 행동을 모든 학습자 공통 순서도로 그릴 수 있나? → 가능하면 워크플로우, 불가능하면 에이전트."*

## 1.5.6 제품 성숙도 3단계 (에이전트성 ↑)
```
Stage 1 [지금]   반응형 워크플로우       일기→문장→표현→피드백
Stage 2 [다음]   반응형 + 개인화 두뇌    에이전트가 target 결정 → 맞춤 → 모델 갱신
Stage 3 [북극성] 능동형(proactive)      유저 입력 없이 AI가 먼저 말 검 (when까지 자율 결정)
```

## 1.5.7 동기 설계 — 외적보상 배제 + 퍼즐=몰입 가설
**핵심 철학: 외적보상(점수·뱃지) 전면 배제.** 순수 내적동기 — *문장을 만들고 맞추는 쾌감*으로 스스로 유입.

### 근거 1) 자기결정이론(SDT)
외적보상은 내적동기를 밀어냄(과잉정당화). 배제가 정답. 내적동기 3요소를 이미 충족:
| SDT 욕구 | 우리 앱 |
|---|---|
| 유능감(competence) | 문장 맞춘 **쾌감** ← 핵심 동력 |
| 자율성(autonomy) | 내 이야기로 내가 씀 |
| 관계성(relatedness) | 능동형 말걸기(Stage 3) |

### 근거 2) 퍼즐 가설 = 몰입(Flow) 이론
> 창업 가설: **언어학습 = 퍼즐게임.** 규칙(문법) + 조각(단어) → 조합해 뜻 만들고 맞추기.

이는 **몰입(Csikszentmihalyi)** 과 동일: *난이도 ≈ 실력*일 때 몰입. 그리고 **몰입 = i+1**.
→ 직관(퍼즐의 재미)과 학습과학(i+1 난이도)이 같은 것.

### 효과↔지속 충돌의 해소 (이전 가설 정정)
이전 v0: "효과 vs 지속 충돌". → **퍼즐=몰입 철학이 이를 해소.**
```
        효과 ─┐
              ├─ 몰입(적정 난이도) ── 같은 지점에서 만남
        지속 ─┘   풀리는 쾌감 = 학습 = 다시 오게 만듦
```
**몰입 지점(난이도=실력)에서 효과와 지속이 수렴.** 외적보상 없이 "스스로 유입"되는 메커니즘.

### RL 프레이밍 정밀화
외적보상 없음 → RL의 보상 신호 = **내적보상(맞춘 쾌감)**. 따라서:
> AI = 보상 *분배기*가 아니라 **몰입 설계자(flow architect)**. 핵심 결정 = **"몰입을 유지하는 난이도의 퍼즐(target) 고르기."**
→ 학습자 모델은 *"현재 실력선 = 몰입 난이도 위치"* 를 추적해야 함 (2장 직결).

## 1.5.8 정직한 리스크 (세미나 검증 대상)
1. ⚠️ **번역 ≠ 직접 사고**: 한→영 번역 구조는 *번역 능력*만 키울 위험. 목표는 "외국어로 *직접* 사고". → **세미나 1순위.**
2. ⚠️ **퍼즐(닫힌 정답) ≠ 언어(열린 소통)**: 정답 1개 맞추기에 과최적화하면 *유연한 소통*이 아니라 *그 한 정답 찾기*를 훈련시킬 위험. 퍼즐 프레임은 **체화·자동화 엔진엔 정확**하나 *열린 의사소통 역량*은 미보장. 설계 포인트: 부분정답/복수정답 처리. → **세미나 질문.** (#1과 같은 뿌리)
3. **알림 피로**: 능동형 말걸기는 잘못하면 짜증. 에이전트가 "말 걸 권리"를 데이터로 벌어야 함.
