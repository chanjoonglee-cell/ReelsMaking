## 0. 배경 — 지금 서 있는 자리

- **자금**: IR을 거쳤지만 최종 조달은 융자 + 정부 창업지원. 12월 말까지 캐시 확보.
- **다음 라운드**: 27년 1분기 투자/보증 — 우리 매출 성과에 달림.
- **투자자 피드백 2가지** (에듀테크·학생창업 특성):
  - 매출이 높다고 투자하지 않음 → **"안 망할 팀"인가** (운영 프로세스·원칙).
  - **신뢰도** → POC 검증. 예: 업스테이지·KT 학습 에이전트 POC 공고 검토 중.
- **모태**: 우리는 **데이터 전략 연구실.** 어떤 데이터를 모아, 어떻게 가공해, 어떻게 되돌려줄 것인가.
- **프레임**: "대표는 더 큰 그림과 구조를 고민하라"는 피드백대로, 고민을 기능이 아니라 **하나의 엔진**으로 정리 — *데이터를 모으고 → 측정·피드백하고 → 자동 개선.* 이 엔진을 네 축에 적용.

```
[1] 유저/시장 데이터  ← 토대 (의사결정 기준: 멘탈모델·JTBD)
      ├──▶ [2] 제품 기능 (LLMOps → Agent)
      └──▶ [3] 마케팅 소구포인트 (소재 자동생성)
[4] 팀 / 회사 OS  ← 위 세 축이 모여 학습되는 메타 레이어
```

## 1. 유저/시장 — 데이터 획득

- 지금 **가장 약한 축.** 제품에만 집중해온 탓에 유저 데이터가 반쪽 — **행동 데이터만** 존재.
- 세 종류를 주기적으로 쌓는 구조로 개편:
  - **정성** — 유저 인터뷰 (DNA 협업, 기존 데이터는 노후화)
  - **정량** — 앱 내 survey 주기 수집 (신규 구축)
  - **행동** — Mixpanel, Firebase 등 (유일하게 확보 중)
- 종합 → **의사결정 기준**: 유저의 **멘탈 모델**, **JTBD.**
- **전제**: 유저 데이터가 모여야 제품 기능도, 마케팅 소구포인트도 나옴. 나머지 축의 토대.
- **타겟**: 초급↔중급. 영어 자체가 무섭고 어디서부터 할지 모르는 층 → *"일기만 쓰세요, 나머지는 저희가."*
  - 핵심 결제층: 결제력 높은 중년 여성. 2030 여성은 액티베이션.
- **막히는 지점**: 정성·정량·행동을 **하나로 종합**하는 방법. 따로 쌓이면 의미 없음.

## 2. 제품 — LLMOps → AI Agent

- **현황**: LLM 약 14개를 묶은 LLMOps. 대외 포지션은 *일기.* 일기 → 분석 → 한 문장 슬라이싱 → 표현 연습 → 자동 저장 → 누적 데이터 제공.
- **프롬프트 Ops를 하면서 느낀 점**이 전환점:
  - 감으로 프롬프트를 고치다 측정해보니 감이 위험했음.
  - 되묻기 버그("Sure! Please provide…") — 측정 없었으면 유저가 빈 응답 받는 걸 못 봤을 손실.
  - → 결론: **LLMOps가 필요하다.** 세 요소를 시스템으로:
    - **Evaluation** (할루시네이션↓) — 유저 신고/수정 → 데이터 축적 → 재학습 루프.
    - **Latency** (렉 없는 경험).
    - **모델·토큰 비용** 최적화.
- **구조적 의미**: 이게 **"딥테크"라 주장할 지점.** 투자사 의문도 여기("GPT 래핑과 뭐가 다르냐"). POC(KT·업스테이지)도 이게 돼야 쉬움.
- **다음 칸**: LLMOps → **Agent.** 차이 = 정서·의미·맥락 기억 + 먼저 말 걸기 + 실시간 조정(챗봇·전화영어). 와우 포인트·확장성·기술 인증.
- **하반기 에이전트 후보 단계**:
  - RAG 기반 **기억 고도화** (개인화)
  - **자동 복습 시스템** (복습 타이밍 자동 계산)
  - 누적 데이터로 **먼저 말 걸기·제안** (D7까지 데이터면 페르소나 도출 가능)
  - **난이도·관심사 조절**
- **확장성**: 영어 → 한국어, 나아가 금융·수학. **학습 메커니즘 자체를 판매.**
- **막히는 지점**: 2개월 스코프. 후보 중 **첫 한 칸**을 무엇으로. → 멘토 판단 필요: 기술 깊이는 어디서 나오나.

## 3. 마케팅/결제 — 소구 포인트 & 소재 자동 생성

- **검증된 사실**: LLMOps만으로도 결제 발생. 해외 ROAS **350~400%** (광고 20만 원 → 매출 약 70만 원).
- **가장 큰 미궁**: *유입*은 어느 정도 알지만 **왜 결제하는지 모름.**
- **결제 가설** (검증 대상):
  - 초기 유저 → **감정 자극**(기대감)으로 결제.
  - 신중 유저 → 에이전트로 **체감**("진짜 늘고 있네") → 결제 → 찐팬 → 바이럴·레퍼럴.
  - 기능적으로 **CES(고객 노력)** 를 낮춰야 함.
- **검증된 세그먼트 — 북미 한인 교민**:
  - 생존 영어 필요 / 어학원은 물리적 거리 / 한 문장씩 교정 → 친절 / 달러 결제로 저렴.
- **포지셔닝**: **보조교재.** 유니크 = 개인 데이터를 쓰며 *한 문장씩 제대로* 학습. 스픽과 싸우지 않고 함께. 가격 경쟁 대신 **많이 쓰게 → 결제 전환율↑.**
- **소재 자동 생성** (조건부): 지금은 추적만 함. 유저 데이터 기반 소구 포인트 → 소재 자동 생성이 목표. **단, 1번이 선행.** 입장: 2개월 안엔 미룸.
- **막히는 지점**: 결제 동인을 8 스프린트로 어떻게 특정할 것인가 (감정 vs 체감 분리).

## 4. 팀/조직 — 회사 OS

- **실패에서 출발한 고민.** KPI 대시보드 시도 → 생각보다 어려웠음.
- 파보니 문제는 대시보드가 아니라 **데이터가 한 곳에 안 모여 있다는 것** (유저/제품/마케팅이 따로).
  - → 대시보드 문제가 아니라 **"팀 OS 문제"**로 재정의. 둘은 연결됨.
- **만들려는 것**: 화면이 아니라 구조.
  - 기록은 슬랙·노션·피그마·Claude 한 곳으로, 모두가 볼 수 있게(public).
  - 스프린트 종료 시 유저 반응·결제·리텐션·회고가 한 곳에 모이고 → AI가 맥락을 읽어 *"이번 병목은 여기, 다음은 여기 집중"* 짚어주는.
  - 결국 **팀 자체를 하나의 학습 에이전트로.** 팀원 개개인은 raw data를 쌓고, AI가 의사결정을 보조.
- **막히는 지점**: "어디서부터?"
  - 인프라부터 제대로 깔지, 아니면 *"기록은 무조건 public 채널에"* 원칙만 세우고 도구는 나중에.
  - 대시보드처럼 완벽주의로 삽질할 위험. → 멘토 판단 필요: 최소 구성.

## 5. 정리

- 의존 구조상 우선순위: **[1] 유저/시장 → [2] 제품 → [4] 팀 OS** 가 토대, **[3] 마케팅(소재 자동생성)** 은 뒤.
- 네 축을 2개월에 다 하려는 게 욕심일 수 있음.
- **멘토에게 듣고 싶은 한 가지**: 무엇을 먼저 깔고, 무엇을 이번 분기엔 버려야 하나.
- **남은 가장 큰 물음표**: 왜 결제하는가 (3번). 이걸 모른 채 연말 마케팅을 태우는 게 가장 큰 리스크.
