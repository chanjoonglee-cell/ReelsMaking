- **자금**: IR을 거쳤지만 최종 조달은 융자 + 정부 창업지원. 12월 말까지 캐시 확보.
- **다음 라운드**: 27년 1분기 투자/보증 — 우리 매출 성과에 달림.
- **투자자 피드백 2가지** (에듀테크·학생창업 특성):
  - 매출이 높다고 투자하지 않음 → **"안 망할 팀"인가** (운영 프로세스·원칙).
  - **신뢰도** → POC 검증. 예: 업스테이지·KT 학습 에이전트 POC 공고 검토 중.
- **모태**: 우리는 **데이터 전략 연구실.** 어떤 데이터를 모아, 어떻게 가공해, 어떻게 되돌려줄 것인가.
- **프레임**: "대표는 더 큰 그림과 구조를 고민하라"는 피드백대로, 고민을 기능이 아니라 **하나의 엔진**으로 정리 — *데이터를 모으고 → 측정·피드백하고 → 자동 개선.* 이 엔진을 네 축에 적용.

```
[1] 유저/시장 데이터  ← 토대 (의사결정 기준: 멘탈모델·JTBD)
      ├──▶ [2] 제품 기능 (LLMOps → Agent)
      └──▶ [3] 마케팅 소구포인트 (소재 자동생성)
[4] 팀 / 회사 OS  ← 위 세 축이 모여 학습되는 메타 레이어
```

## 1. 유저/시장 — 데이터 획득

**현황**
- 지금 **가장 약한 축.** 제품에만 집중해온 탓에 유저 데이터가 반쪽 — **행동 데이터만** 존재.
- 행동(Mixpanel·Firebase)은 *무엇을* 하는지는 보여주지만 *왜* 하는지는 모름.

**하려는 것**
- 세 종류를 주기적으로 쌓는 구조로 개편: **정성**(유저 인터뷰, DNA 협업) · **정량**(앱 내 survey) · **행동**(Mixpanel·Firebase).
- 종합 → **의사결정 기준**: 유저의 **멘탈 모델**, **JTBD.** 이게 있어야 제품 기능도, 마케팅 소구점도 나옴.

**구체적 고민**
- **세 데이터가 층위가 다르다.** 정성은 깊지만 표본이 작아 일반화가 어렵고, 정량은 넓지만 응답 편향이 있고, 행동은 객관적이지만 동기를 모름. 이 셋을 *하나의 멘탈모델로 묶는* 방법을 모르겠음. 그냥 따로 쌓이면 보고서 3개가 될 뿐.
- **종합의 주체와 산출물.** 누가 이걸 종합하나(나? 디애나?). 산출물이 페르소나 문서인지, JTBD 맵인지, 아니면 "이번 스프린트 의사결정 1줄"인지 — 형태가 안 잡힘.
- **주기화의 현실성.** 매 스프린트(2주)마다 인터뷰를 돌릴 수 있나? 정량 서베이를 자주 띄우면 유저 경험을 해침. *데이터를 얻으려다 제품을 망치는* 트레이드오프.
- → 멘토 판단 필요: 작은 팀에서 정성·정량·행동을 **하나로 종합하는 최소 구조**가 뭔가.

## 2. 제품 — LLMOps → AI Agent

**현황**
- LLM 약 14개를 묶은 LLMOps. 대외 포지션은 *일기.* 일기 → 분석 → 한 문장 슬라이싱 → 표현 연습 → 자동 저장 → 누적.
- **Prompt Ops를 직접 하면서** 측정의 중요성을 체감. 감으로 고치다 측정하니 감이 위험했음 (되묻기 버그 "Sure! Please provide…" — 측정 없었으면 유저가 빈 응답 받는 걸 못 봤을 손실).

**하려는 것**
- LLMOps 세 요소를 시스템으로: **Evaluation**(할루시네이션↓, 유저 신고→재학습 루프) · **Latency** · **모델/토큰 비용.**
- 그 다음 **Agent로**: 정서·맥락 기억 + 먼저 말 걸기 + 실시간 조정(챗봇·전화영어).

**구체적 고민**
- **"딥테크"의 경계가 어디인가.** 투자사 의문이 "GPT 래핑과 뭐가 다르냐"였는데, 솔직히 나도 *어디까지가 우리 기술이고 어디까지가 프롬프트 엔지니어링인지* 선이 안 선다. eval을 자체 구축하면 기술인가, LangSmith 같은 거 붙이면 끝인가. 투자사·POC에 **뭘 보여줘야 "기술 깊이"로 인정**받는지 모르겠음.
- **에이전트 첫 한 칸 선택.** 후보 4개가 성격이 다 다름:
  - *RAG 기억* — 개인화의 토대지만 인프라가 무겁고 2개월에 버거움.
  - *자동복습* — 리텐션에 가장 직결될 것 같은데, "언제 복습시킬지" 타이밍의 학습과학 근거를 어디서 가져오나.
  - *선제안(먼저 말 걸기)* — 와우 포인트지만 D7치 데이터가 안 쌓이면 빈약함.
  - *난이도 조절* — 체감은 좋은데 측정·평가가 까다로움.
  - → 무엇이 *결제 체감*에 가장 직결되는지 기준으로 골라야 하는데 판단이 안 섬.
- **2개월 리소스 현실성.** 개발이 동재·민준 둘인데, 8 스프린트 마케팅을 돌리면서 에이전트까지 만드는 게 가능한가. 욕심 아닌가.
- → 멘토 판단 필요: 기술 깊이는 이 중 어디서 나오나 / 첫 한 칸은 무엇으로.

## 3. 마케팅/결제 — 소구 포인트 & 소재 자동 생성

**현황**
- LLMOps만으로도 결제 발생. 해외 ROAS **350~400%** (광고 20만 원 → 매출 약 70만 원), 북미 한인 교민에서 검증.
- 포지셔닝은 **보조교재** — 개인 데이터를 쓰며 한 문장씩 제대로. 스픽과 싸우지 않고 함께.

**하려는 것**
- 마케팅 데이터 *추적*을 넘어 → 유저 데이터 기반 **소구 포인트 → 소재 자동 생성.**

**구체적 고민**
- **왜 결제하는지를 모른다 (가장 큰 미궁).** 유입 동선은 어느 정도 아는데, 결제 버튼을 누르는 *진짜 이유*를 모름. ROAS 350%가 소액에서 나온 건데, 이걸 모른 채 연말에 크게 부으면 **스케일하는 순간 깨질까 봐** 무섭다. 이게 LTV/CAC 전체의 가장 큰 리스크.
- **감정 vs 체감을 어떻게 분리하나.** 가설은 "초기유저=감정 자극, 신중유저=효과 체감"인데, 페이월 A/B로 분리 측정하려 해도 우리 트래픽에서 *통계적으로 의미 있는 표본*이 나오는지 모르겠음.
- **소재 자동생성의 닭-달걀.** 유저 데이터 기반으로 소재를 만들고 싶은데, 그 데이터가 아직 없음. 그래서 1번이 선행돼야 하고, 2개월 안엔 미루는 게 맞다고 보는데 — *이 판단이 맞는지*, 1번과 동시에 가볍게 깔 방법은 없는지.
- → 멘토 판단 필요: 결제 동인을 8 스프린트로 특정하는 현실적 설계가 있나.

## 4. 팀/조직 — 회사 OS

**현황**
- **실패에서 출발한 고민.** KPI 대시보드를 시도했으나 생각보다 어려웠음.
- 파보니 문제는 대시보드가 아니라 **데이터가 한 곳에 안 모여 있다는 것** (유저/제품/마케팅이 따로). → "대시보드 문제"가 아니라 **"팀 OS 문제"**로 재정의.

**하려는 것**
- 모든 기록을 한 곳으로(슬랙·노션·Claude, public) → 스프린트 종료 시 유저 반응·결제·리텐션·회고가 모이고 → AI가 맥락을 읽어 *"이번 병목은 여기, 다음은 여기 집중"* 짚어주는.
- 결국 **팀 자체를 하나의 학습 에이전트로.** 팀원 개개인은 raw data를 쌓고, AI가 의사결정을 보조.

**구체적 고민**
- **대시보드가 왜 실패했는지 아직 진단이 안 됨.** *(a)* 뭘 봐야 할지 질문을 안 정해서인지, *(b)* 데이터가 애초에 없어서인지, *(c)* Mixpanel 툴의 한계인지 — 이 셋이 안 갈림. 진단을 못 하니 다음 시도도 또 실패할까 봐 두렵다.
- **기록-구조화의 딜레마.** AI가 읽게 하려면 기록이 구조화돼야 하는데, 구조화를 강제하면 팀원이 *기록 자체를 안 함*. 반대로 자유롭게 쌓으면 노션에 글이 쌓여도 *아무도 안 보고 AI도 못 읽음.* 이 트레이드오프를 어디서 잡나.
- **시작점 딜레마.** 인프라(통합 DB·파이프라인)부터 제대로 깔지, 아니면 *"기록은 무조건 public 채널에"* 원칙 하나만 깔고 도구는 나중으로 미룰지. 대시보드처럼 또 완벽주의로 몇 주를 태울까 봐 걱정.
- **public 원칙의 부작용.** private DM을 금지하면 투명성은 오르지만 심리적 안전감을 해칠 수도. 작은 팀에서 이 균형을 어떻게.
- → 멘토 판단 필요: "데이터가 모이고 AI가 회고를 돕는" 구조의 **최소 구성**과 시작점.

## 5. 정리 — 멘토에게 듣고 싶은 것

- 의존 구조상 우선순위: **[1] 유저/시장 → [2] 제품 → [4] 팀 OS** 가 토대, **[3] 마케팅(소재 자동생성)** 은 뒤.
- 네 축을 2개월에 다 하려는 게 욕심일 수 있음. 개발 리소스(동재·민준 2명)로 8 스프린트 + 에이전트 + 회사 OS를 동시에?
- **멘토에게 듣고 싶은 한 가지**: 무엇을 먼저 깔고, **무엇을 이번 분기엔 버려야 하나.**
- **남은 가장 큰 물음표**: 왜 결제하는가 (3번). 이걸 모른 채 연말 마케팅을 태우는 게 가장 큰 리스크.
