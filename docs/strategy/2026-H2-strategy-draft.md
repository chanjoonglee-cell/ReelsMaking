## 0. 한 장 요약

```
[지금]  AX·PRD로 인프라 세팅 중 / 자금은 융자+정부지원으로 12월까지 캐시 확보
   │
[목표]  6~10월 8 스프린트로 데이터 축적·검증
   │ → 10~11월 마케팅 풀 ON으로 매출 우상향
   │ → 12~1월 공격적 마케팅으로 매출 피크
   │
[다음]  매출 그래프 + POC(신뢰)로 27년 1분기 투자/보증 → 스케일업 → 내년 글로벌
```

**북극성 지표: LTV / CAC**

## 1. 배경 — 우리가 지금 어디에 서 있나

- **자금**: IR을 거쳤지만 최종 조달은 **융자 + 정부 창업지원**. 12월 말까지 캐시 확보됨.
- **다음 라운드**: 27년 1분기 안에 보증 또는 투자 — **우리 매출 성과에 달려 있음.**
- **투자자 피드백 2가지 (에듀테크·학생창업 특성상):**
  1. 매출이 높다고 투자하지 않는다 → **"안 망할 팀"인가**: 운영 프로세스·원칙이 잡혀 있나.
  2. **신뢰도가 있나** → POC 검증(대기업 협업)이 신뢰를 만든다.
     - 예: 업스테이지·KT의 **학습 에이전트 POC 공고** — 참여 검토 중.
- → **신뢰가 높아야 밸류에이션이 올라간다.** 그래서 이번 반기는 *매출 + 신뢰* 둘 다 쌓는다.

---

## 2. 우리의 모태 — 데이터 전략 연구실

- 우리는 **데이터 전략 연구실**이다.
  - *어떤 데이터를 모을 것인가 / 어떻게 가공할 것인가 / 어떻게 다시 제공할 것인가.*
- **연구 주제: 모바일 언어학습의 이탈률↓ · 학습 지속성↑**
- 핵심 관찰: **언어학습은 모바일 퍼즐게임과 원리가 동일하다.**
  - 문법·규칙이 있고, 단어를 조합해 정답(인출)을 만든다.
  - 그런데 왜 *공부는 시켜도 안 하고, 퍼즐 게임은 시켜도 할까?* → 이 간극을 푸는 게 우리 일.

## 3. 사업의 3축 & 피드백 루프

```
   유저/시장  ──▶  DB  ──▶  프로덕트/솔루션  ──▶  마케팅/결제  ──▶  (재유입)
       ▲                                                              │
       └──────────────────────── 피드백 루프 ───────────────────────────┘
```

**현재 진단: 루프가 반쪽이다.** 그동안 프로덕트에만 집중 (AX·PRD도 사실상 프로덕트 인프라).
유저 데이터가 행동 데이터(Mixpanel·Firebase)뿐 → 정성·정량이 약하다.

### 유저 데이터 개편 (2가지)
| 종류 | 현재 | 개편 |
|---|---|---|
| 행동 (자동) | ✅ Mixpanel, Firebase | 유지 |
| 정성 (인터뷰) | ⚠️ 간헐적·노후화 | **주기적 유저 인터뷰** (DNA 합류) |
| 정량 (직접 응답) | ❌ | **인앱 서베이 주기 수집** |

> **결론: 3축 중 가장 주기적으로 잘 모아야 할 데이터는 `유저·시장`이다.**
> 제품도 마케팅도 결국 유저 니즈에서 구현되고, 시장은 살아 움직이기 때문. → **고객 개발을 계속한다.**

### Q1. 유저·이론 — 왜 이탈하는가

- 이탈이 높으니 구독제로밖에 못 풀고, 그래서 투자자가 불신한다. → **이탈률을 낮추는 게 코어.**
- **리텐션 가설: R = M · A / C**  (리텐션 ∝ 동기 × 성취 / 인지부하)
  - 학습 = 정보 습득 → **인출**. 인출에 에너지가 많이 들어 병목·인지부하 발생.
- **문제 재정의**: 언어학습은 *내 생각을 표현*하는 것. 그런데 대부분 앱은 **남의 생각**을 표현하게 하고, 순간적 의지를 구독제로 판다 → 마케팅 비대, 제품 빈약.
- **→ 우리의 정체성: 자기참조 기반 인출학습 (Self-referential Retrieval)**
  - 자기 관련 정보 + 정서·난이도 맞춤 + 하루 5분, 1~5문장.
  - 즉각 반응 → 성취 누적 → 습관화 (D1 → D7 → D21 → D66).
  - 데이터가 쌓일수록 맞춤형 제공 → 하나의 큰 데이터 플로우.
  - (이론화 과제: 인지심리 · 학습과학 · 데이터사이언스 결합)

---

### Q2. 제품·솔루션 — LLMOps → Agent

**현재 (LLMOps):** LLM 약 14개 묶음. 대외 포지션은 *일기*.
일기 작성 → LLM 분석 → 한 문장씩 슬라이싱 → 표현 연습 → 자동 저장 → 누적 데이터 제공.

**다음 (Agent):** LLMOps를 넘어선다.
- 차이: 에이전트는 **정서·의미·맥락을 기억**하고, **먼저 말 걸고**, 실시간 조정한다. (챗봇·전화영어 수준)
- 와우 포인트·확장성·기술 인증이 여기서 나온다.

**LLMOps 운영 3요소 (병행):**
1. **Evaluation** — 할루시네이션↓. *유저 신고/수정 버튼 → 데이터 축적 → 재학습 → 퀄리티 향상* 루프.
2. **Latency** — 렉 없는 경험.
3. **모델·토큰 비용 최적화** — 스무스하게, "외국인 친구와 대화하는" 정서적 느낌.

**하반기 에이전트 단계 (후보):**
- RAG 기반 **기억 고도화** (개인화)
- **자동 복습 시스템** (복습 타이밍 자동 계산)
- 누적 데이터로 **먼저 말 걸기·제안** (일기 안 써도)
- **난이도·관심사 조절** → 모바일에서 인출 경험 재현

**페르소나 프롬프트 4축:**
① 페르소나 심층 분석 → ② 데이터 분석 → ③ 표현 생성(지역·맥락: 영/미 등) → ④ Evaluation·피드백 → 사이클 반복

> POC 측면: 에이전트가 되면 KT·업스테이지 같은 POC가 훨씬 쉽다. (카이스트 학습 스타트업 = 기술 신뢰)
> 확장성: 영어 → 한국어, 나아가 금융·수학 등 **학습 메커니즘 자체를 판다.**

### Q3. 시장·결제 — 왜 결제하는가

**검증된 사실:** LLMOps만으로도 결제는 이미 나온다.
- 해외 ROAS **350~400%** (광고 20만 원 → 매출 약 70만 원). 크게 부으면 더 키울 여지.

**아직 모르는 것:** *유입*은 어느 정도 알지만, **왜 결제하는지**는 모른다.
- 추정: 돈 여유 있고 영어 의지·감정이 강함 → **감정을 잘 건드는 B2C 앱**을 원한다.

**결제 유도 가설 (검증 대상):**
- 초기 유저 → **감정 자극**("진짜 늘 것 같다"는 기대감)으로 결제.
- 신중 유저 → 에이전트로 **체감**("진짜 늘고 있네")했을 때 결제 → 찐팬 → 바이럴·레퍼럴.
- 기능적으로 **CES(고객 노력)** 를 낮춘다.

**검증된 세그먼트 — 북미 한인 교민 (왜 결제했나):**
- 생존 영어가 필요 / 영어 약함 / 어학원은 물리적 거리.
- 직접 쓸 표현을 바로바로, **한 문장씩 교정** → 친절함.
- 일기 특성상 모국어로 쓰며 **감정적 터치**. / **달러 결제 → 훨씬 저렴.**

**포지셔닝:** 시장에서 **보조교재**.
- 유니크: 개인 데이터를 쓰면서 *무조건 많이 말하기*가 아니라 **한 문장씩 제대로** 학습시키는 유일무이한 앱.
- 스픽 등과 *싸우지 않고 함께* 쓴다. → 가격 경쟁 대신 **많이 쓰게 → 결제 전환율↑.**

**시장 정의 (4분면):**
| 영역 | 예시 | 우리가 배우는 것 |
|---|---|---|
| 모바일 퍼즐게임 | — | 규칙+조합+인출 = 언어학습과 동일 원리 |
| 습관성 멘탈케어·기록 | 운동기록·집중력 앱 | 어려운 걸 캐주얼하게, 계속하게 |
| 캐주얼 언어학습 | 듀오링고·링고디어·드롭스 | 하루 5분 짧게짧게 |
| 폐쇄형 소셜 | 셉(소수 지인 소셜) | 친밀한 정서적 연결 |

**타겟:** 초급↔중급을 오가는 층.
- 영어 자체가 무섭고 어디서부터 할지 모르는 사람 → *"일기만 쓰세요, 나머지는 저희가."*
- 핵심 결제층: **결제력 높은 중년 여성** / 2030 여성은 액티베이션 유저 / (희망: 영유아까지 확장)

### Q4. 팀·운영 — 학습하는 조직 / 회사 OS

- 우리 조직도 **데이터가 흐르고 학습돼야** 한다. 스스로 회고·인출엔 한계 → **AI가 맥락을 읽게 DB 일원화.**
- 기록은 모두 **슬랙·노션·피그마·Claude** 한 곳으로 → **모두가 볼 수 있게** 쌓는다.
- 매 회고에서 **유저 반응 · 제품 · 시장/결제 · 사업 상황 · 팀 상태**를 함께 점검.
- *학습 = 새 정보를 받아 인출해 체화 → 최적화 → 성장.* 같은 원리를 **팀·유저 양쪽에** 적용.

## 5. 팀 워크플로우 (스프린트 1사이클)

```
[리서치]  찬중(이론·논문) + 지안(UX·앱 경험) + 디애나(유저)
   └─▶ [배경문서] 찬중 ─▶ [PRD] 지안 ─▶ [개발 검토]
        └─▶ [와이어프레임] 동재·민준 ─▶ [개발 리뷰] ─▶ [개발]
             └─▶ [QA] (자동화 검토) ─▶ [배포] ─▶ [회고]

  ※ 개발 공백기 — 찬중: 케이스 리서치 + 마케팅 세팅 + 프롬프트 개선
  ※ 배포 직전 — 찬중: 소구 포인트 + 메타 광고 (+ 인플루언서/오가닉/커뮤니티·CRM)
```

**회고 고정 안건:**
1. 마케팅이 얼마나 먹혔나
2. 결제 전환이 얼마나 됐나
3. 제품 리텐션 (D1·D7)
4. 결제/비결제·이탈/잔존 유저 패턴 → 다음 유저 리서치 입력(디애나)
5. 마케팅 소구 키워드 → 시장을 잘 잡았나

- → *마케팅발 리텐션 vs 제품발 리텐션 분리* (인과 추론)

## 7. 비즈모델 진화 & 비전

```
구독제  ──(리텐션↑)──▶  F2P + 마이크로페이먼트  ──▶  B2B / B2C 확장  ──▶  글로벌(북미)
```

- 리텐션이 높아지면 구독 모델을 벗어나 **F2P + 마이크로페이먼트**로 간다.
- 매출 그래프 + POC 성공 → **신뢰도↑ → 밸류↑**.
- 외부 위기에도 버티는 팀 → 투자/보증 → 스케일업.
- **내년: 국내를 확실히 키운 뒤 북미 등 글로벌 진출.**
