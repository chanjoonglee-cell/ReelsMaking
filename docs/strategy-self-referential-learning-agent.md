# 자기참조형 인출 기반 학습 AI 에이전트 — 전략 문서

> 한 문장 요약: **학습자 자신을 학습 소재(코퍼스)로 삼아, 난이도를 낮추지 않고 자기참조성으로 동기를 공급함으로써 "학습효과"와 "지속"을 동시에 달성하는 AI 튜터 에이전트를 만든다. 이를 위해 "진단 → 개입(떠먹이지 않는 소크라틱) → 측정 → 기억 → 적응"의 닫힌 루프를, 평가·관측 가능한 LLMOps 토대 위에서 돌린다.**

---

## Part I. 이론적 토대 (Why)

### 1.1 출발 모순
공부와 게임의 원리는 같은데, 왜 게임은 시키지 않아도 하고 공부는 시켜도 안 하는가. 차이의 핵심은 **자기참조성(Self-Referentiality)** — 게임의 소재는 학습자의 취향·상호작용에서 비롯되어 동기가 강하지만, 전통적 학습의 소재는 학습자와 무관하고 비상호작용적이라 이탈한다. 언어학습에서 이 차이는 가장 선명하다: 결정적 변수는 "그 문장이 나와 관련 있는가"이며, 소재를 자신의 생각·경험으로 삼으면 '연습'과 '표현'의 간극이 사라진다.

### 1.2 본질적 딜레마 — 학습효과 vs 지속의 상충
- **인출(Retrieval)**: 학습과학에서 입증된 핵심. 단순 반복·쉐도잉과 달리, 백지에서 산출하는 인출만이 학습을 자동화한다.
- **문제**: 인출은 높은 인지부하를 수반한다. 이 부하는 학습효과의 원천이라 제거할 수 없지만(바람직한 어려움), 바로 그 부하 때문에 모바일에서 이탈이 일어난다.
- **기존 흐름의 반쪽 해법**:
  - 게임화·스트릭 → 재방문은 올리나 학습과 분리된 **"가짜 재방문"**에 머문다.
  - 학습과학 → 학습효과는 높이나 높은 부하로 이탈을 유발하며, '지속'을 설계 차원에서 다루지 않았다.
- 두 목표는 상충하며("난이도를 낮추면 학습이 빠진다"), **"학습이 동반된 지속"은 검증되지 않은 빈칸**으로 남아 있다.

### 1.3 핵심 통찰 — 직교성(Orthogonality)
자기참조성은 **난이도 축이 아니라 동기 축**에서 작동한다. 즉 인출의 바람직한 어려움을 보존(난이도 유지)하면서, 친숙한 자기 스키마로 **외재적 인지부하만 낮추고** 동기를 별도 채널로 공급한다. 이로써 기존의 trade-off(난이도↓=학습↓)를 우회한다. **이것이 본 전략의 엔진이다.**

### 1.4 자기참조성의 3차원
| 차원 | 정의 | 기억효과 근거 |
|---|---|---|
| 자기관련성 | 소재가 학습자의 관심·정체성과 연결되는 정도 | 처리수준 효과 |
| 자기경험성 | 소재가 학습자의 실제 삶·경험에서 비롯되는 정도 | 정서적 자전기억 공고화 |
| 자기표현성 | 학습자가 자기 생각을 직접 산출하는 주체가 되는 정도 | 생성효과 |

위계: 자기관련성이 토대, 경험성·표현성이 그 위에서 개입을 심화. **언어학습에서는 목적 자체가 자기표현이므로 자기표현성이 결정적.**

### 1.5 3경로 — 자기참조성이 지속에 이르는 길
1. **동기 경로** — 자율성·관련성 욕구 충족 → 내재적 동기 → 지속. (매 세션 즉각)
2. **학습효과 경로** — 외재적 부하↓ + 인출 보존 → 성취 → 자기효능감 → 지속. (매 세션 즉각)
3. **애착 경로** — 누적 기록이 '확장된 자기'가 됨 → 정서적 애착 → 장기 지속. (데이터가 쌓여야 작동)

### 1.6 명제 (검증 대상)
- P1(동기): 자기참조성↑ → 내재적 동기 매개 → 지속↑
- P2(학습효과): 자기참조성↑ → 자기효능감 매개 → 지속↑
- P3(애착): 자기참조 데이터 누적↑ → 기록 애착 매개 → 장기 지속↑
- P4(경계조건): 학습목적이 자기표현적일 때(언어·글쓰기) 강하게, 무관할 때(수식·암기) 약하게. (반증선)

### 1.7 실현 가능성의 전제
이러한 자기참조 인출 학습은 학습자의 자유로운 표현을 **실시간 교정**할 수 있어야 가능하며, 이는 대규모 언어모델(LLM)의 등장으로 비로소 실현되었다.

## Part II. 학습 에이전트의 정의와 원칙

### 2.1 챗봇 vs 학습 에이전트
> 챗봇은 **답을 한다.** 학습 에이전트는 **학습자의 지식 상태를 진단하고, 개입하고, 변화를 측정하고, 그 변화를 기억해 다음 개입을 적응시킨다.** — 학습자를 변화시키고 그 변화를 추적하는 닫힌 루프가 본질이다.

### 2.2 닫힌 학습 루프
```
        ┌──────────── 학습자 모델 (척추) ────────────┐
        │                                          │
   진단 ──→ 개입 ──→ 측정 ──→ 기억·갱신 ──→ 적응 ──┘
   (무엇을      (어떻게      (학습이      (자기참조      (다음을
    틀렸나)      가르치나)    일어났나)    누적)         맞춤)
        └──────── 평가·운영 (LLMOps 토대) ─────────┘
```
필요 역량은 기능 목록이 아니라 **이 루프의 부품**으로 도출된다.

### 2.3 핵심 설계 원칙
1. **떠먹이지 않는다** — 정답을 즉시 주면 인출(학습효과의 원천)이 사라진다. 정답·모범답안은 *인출 실패 이후의 해소 단계*로만.
2. **난이도는 보존, 부하만 조절** — 힌트·스캐폴딩은 외재적 부하만 낮춘다. 인출 난이도 자체는 지킨다.
3. **학습자를 코퍼스로** — 시스템이 콘텐츠를 공급하는 게 아니라, 학습자의 삶·생각이 학습 재료가 된다.
4. **측정 가능한 것만 신뢰한다** — LLM은 비결정적이므로 평가·관측 없이는 개선도 신뢰도 불가능.

## Part III. 역량 프레임워크 (What)

### 3.0 척추 — 학습자 모델 (Learner Model)
학습자가 무엇을 알고/모르는지, 반복 오개념, 수준·동기 상태를 담는 살아있는 표상. **진단·개인화·적응·측정이 전부 이 모델을 읽고 쓴다.** 가장 먼저 정의해야 할 단 하나의 구조.
- 입력 A: **삶 프로파일** — 관심·인물·장소·활동·감정 (자기참조 소재에서 추출)
- 입력 B: **학습 프로파일** — 오개념 유형별 숙달도, 수준, 인출 성공률
- 두 입력을 통합 → "학습자의 삶과 학습이력을 동시에 아는" 모델

### 3.1 진단 (Diagnosis)
- **의도 진단**: 학습자가 *무엇을 표현하려 했는가*(의미일치). 자기표현성의 측정점.
- **오개념 진단**: *왜 틀렸는가*를 유형으로 분류(O/X가 아닌 원인 분류).
- 전략적 필요성: 진단은 모든 개입과 측정의 입력값. 진단 없는 피드백은 증상만 누른다.

### 3.2 개입 (Intervention)
- 콘텐츠·문제 생성 (학습자 소재 기반)
- 자동 피드백·교정 (학습자 목소리 보존하며 최소교정)
- 소크라틱 발문 (정답 비노출, 단계적 스캐폴딩)
- 인출 스캐폴딩 (단서·힌트·빈칸)
- 전략적 필요성: 개입 품질 = 학습 에이전트의 차별점.

### 3.3 기억·개인화 (Memory & Personalization)
- 장기 학습 이력 (과거 오개념·표현·해소를 검색 가능)
- 자기참조 코퍼스 (학습자 자신의 기록 누적)
- 진척·숙달 추적 (오개념별 극복 여부)
- 전략적 필요성: 개인화의 본질은 "시스템이 맞춤"이 아니라 "학습자 자신의 누적이 재료이자 동기"가 되는 것 → 애착 경로.

### 3.4 적응 (Adaptation)
- 적응형 난이도 / 간격반복 스케줄링 / 학습 경로
- 전략적 필요성: 진단·기억이 다음 행동에 반영돼야 루프가 닫힌다. 적응은 루프를 회전시키는 마지막 고리.

### 3.5 측정 (Measurement)
- 학습효과: 백지 인출 성공률, 오개념 해소율
- 지속: 상태 전이(활성·휴면·이탈), **"학습 동반 지속" vs "가짜 재방문" 구분**
- 동기·정서 신호
- 전략적 필요성: 측정 없는 학습 주장은 검증 불가. 표층 지표(재방문율)가 아닌 학습 내장 지표를 봐야 핵심 가치가 증명된다.

### 3.6 토대 — 평가·운영 (LLMOps / Trust)
- Evaluation(골든셋), 관측(trace), 안전 가드레일(정답 비노출·환각·개인정보)
- 전략적 필요성: 위 전부가 비결정적 LLM 기반. 이 토대가 없으면 안전한 반복 개선이 불가능 → 개발 속도와 신뢰의 전제.

### 3.7 접점 — 입출력 (확장)
멀티모달 입력(경험 소재), 음성(말하기 인출). 차별점이라기보다 표면 경험. 척추가 선 뒤 얹는 증축.

### 3.8 우선순위 요약
| 구분 | 역량 | 성격 |
|---|---|---|
| 반드시(척추+필수루프) | 학습자 모델 · 진단 · 개입(소크라틱) · 기억 | 없으면 "학습 에이전트"가 아님 |
| 루프 완성 | 적응 · 측정 | 루프를 닫고 가치를 증명 |
| 전제 토대 | 평가 · 관측 · 가드 | 위 전부를 안전하게 반복 |
| 확장 | 멀티모달 · 음성 | 표면 경험 |

## Part IV. 시스템 아키텍처 (How — 기술)

### 4.1 전체 구조
```
┌─────────────────────────────────────────────────┐
│              대화 표면 (앱 / 튜터 UI)              │
└───────────────────────┬─────────────────────────┘
                        │
┌───────────────────────▼─────────────────────────┐
│              Agent Orchestrator                   │
│   매 세션: 모드 결정 (RETRIEVE 먼저 → ELICIT)      │
│   턴 상태 보유 (현재 진단·시도횟수·이력)            │
└───┬───────────────┬───────────────┬──────────────┘
    │               │               │
┌───▼────┐    ┌─────▼─────┐   ┌─────▼──────┐
│ LLM 스킬 │    │  결정론 코어 │   │   저장소    │
│ (두뇌)   │    │  (골격)     │   │            │
├─────────┤    ├───────────┤   ├────────────┤
│ 진단     │    │ 스케줄러    │   │ 학습자모델  │
│ 발문     │    │ 상태머신    │   │ 표현/이력   │
│ 채점judge│    │ 항목화      │   │ trace/event│
└─────────┘    └───────────┘   │ RAG 인덱스  │
                                └────────────┘
```
**철칙: LLM은 언어를, 코드는 스케줄·상태·카운팅을.** 스케줄링·상태판정을 LLM에 맡기면 신뢰성이 무너진다.

### 4.2 LLM 스킬 3분리 (독립 함수 + 구조화 출력)
각 스킬을 `(L1, L2)` 파라미터를 받는 독립 함수로 → 튜닝·모델교체·다국어가 쉬워진다.
- **진단(diagnose)** `(학습자답, 정답/의도, 이력) → {의미일치, 오류타입[], 근거, L1전이, recurring}`
- **발문(socratic)** `(오류, 시도횟수, 수준) → {질문(정답 비노출), 스캐폴드레벨}`
- **채점(judge)** `(항목, 응답) → {의미일치, L2정확성, 피드백}` — 문자열 일치❌, 의미 일치⭕

### 4.3 소크라틱 루프 (개입의 핵심)
```
학습자 영어 산출(인출)
   │
   ▼ 진단  ← RAG: 이 학습자 과거 오개념 주입
   │   의미·형태 OK → 강화 + 이력 적재
   │   오류 있음 ↓
   ▼ 소크라틱 발문 (정답 비노출, 오류타입 타겟)
   │   L1: 주의 환기 → L2: 오류타입 명시 → L3: 답 근접(마지막 칸은 학습자)
   ▼ 재시도 → 진단 재진입 (최대 N=2~3회)
   │   초과/포기 → 해소(정답+설명 공개)
   ▼ 이력 적재 (오개념 타입·해소여부 → RAG)
```
주의: 소크라틱 왕복이 길면 그 자체가 부하·이탈 요인 → **N을 짧게(2~3)** 두고 빠르게 해소로.

### 4.4 과제 세부과제 매핑 (Solar LLM 기반 소크라틱 튜터)
| 세부과제 | 아키텍처 대응 | 이론 대응 |
|---|---|---|
| ① 학습자 의도·오개념 진단 | 4.2 진단 스킬 + 오개념 taxonomy | 인출 응답의 의미/형태 판정 |
| ② 소크라틱 발문 생성 엔진 | 4.2 발문 스킬 + 4.3 루프 | 정답 비노출 = 바람직한 어려움 보존 |
| ③ 개인화 학습이력 RAG | 4.5 RAG + 학습자 모델 | 자기참조·애착 |

### 4.5 자기참조 RAG (③)
일반 RAG(외부 문서)가 아니라 **학습자 자신의 과거를 검색**하는 RAG.
- 저장: 과거 표현(자기경험성), **과거 오개념·해소 이력(최고 가치)**, 자기생성 문장(자기표현성)
- 활용: ① 진단 보강(recurring 탐지) ② 발문 개인화 ③ 반복 오개념 간격 재출제
- → "개인화"가 곧 자기참조성, 누적 이력이 곧 "확장된 자기".

### 4.6 모델·provider 전략 (Solar / 데이터 거버넌스)
- provider 추상화(폴백·타임아웃·라우팅)를 둬, 모델 교체를 함수 뒤로 격리. Solar는 provider 추가로 흡수.
- **데이터 거버넌스**: 학습 소재(일기 등)는 고도로 개인적 → 국내 처리(Solar 등)는 단순 비용이 아니라 전략·규제 명분.

### 4.7 데이터 모델 (핵심 엔티티)
```
Learner    { id, L1, L2, state(활성/휴면/이탈), profile(삶+학습), last_active }
Expression { id, learner_id, original(학습자 산출), corrected, faithful, context, created_at }
Item       { id, expression_id, cue(맥락·L1의미; 정답 비노출), target, ease, interval, due_at, lapses }
Review     { id, item_id, response, intent_match, from_blank, errors[], latency, created_at }
Misconcept { learner_id, type, count, last_seen, resolved }   ← 학습자 모델의 핵심
Event      { id, type, payload, created_at }                  ← 측정·연구·관측
```
다국어 확장: L1/L2를 엔티티·프롬프트의 파라미터로만 흘리면, 고정 코퍼스가 없으므로 확장은 거의 공짜.

## Part V. 개발 방법론 (How we work)

### 5.1 성숙도 층 — LLM → LLMOps → Agent
폭포수가 아니라 **층**이다. LLMOps는 Agent를 상시 떠받치는 바닥.
```
┌──────────────────────────────┐
│ Agent   소크라틱 루프 · RAG     │  ← 세운다
├──────────────────────────────┤
│ LLMOps  eval·관측·프롬프트버전   │  ← 받친다(상시)
│         ·data pipeline         │
├──────────────────────────────┤
│ LLM     진단·출제·교정(프롬프트) │  ← 경화한다
└──────────────────────────────┘
```
순서의 본질: **eval-first.** 평가 인프라가 먼저 있어야, 이후 모든 Agent 변경이 "좋아졌는지" 측정된다. (이게 없으면 "데모는 도는데 나아진 건지 모르는" 함정.) 단, **LLMOps를 과적하지 말 것** — PoC는 최소 3종(골든셋+품질로깅+프롬프트버전)만.

### 5.2 경험적 개발 루프 (Inner Loop)
LLM 에이전트는 "설계→구현"이 아니라 "측정→학습"의 반복이다.
```
① 실제 대화(trace) 정독  → ② 실패 모드 분류(→골든셋·taxonomy 반영)
→ ③ 가설+변경(한 번에 하나) → ④ eval(골든셋 자동) → ⑤ 게이트 통과 시 배포
→ ⑥ 운영 관측 → ①
```
심장은 ①(trace 정독). 대시보드 숫자는 "뭐가 잘못됐나"를 못 알려준다 — 실제 대화를 읽어야 실패 모드가 보인다. (error-analysis-driven development)

### 5.3 3개의 진실의 원천 (팀이 자산으로 관리)
1. **골든셋** — 모든 변경이 통과할 시험지(학습자답↔정답↔오개념 라벨). trace에서 실패가 나올 때마다 추가 → 팀의 기억.
2. **프롬프트 레지스트리** — 인라인 프롬프트를 외부화·버전·diff·리뷰. *프롬프트를 코드처럼.*
3. **Trace 로그** — 입력·진단·발문·결과. ①의 재료이자 RAG 메모리이자 연구 데이터. (한 번 깔면 3중 활용)

### 5.4 규율
- 한 번에 한 변수만 변경 (효과 귀속 가능)
- 작고 가역적인 변경 (flag 뒤, 즉시 롤백)
- 변경 종류별 검증 깊이: 프롬프트→골든셋 / 루프→통합테스트 / 모델교체→전체회귀+latency·비용
- DoD = 기능이 도는 것이 아니라 **골든셋 게이트 통과** (예: 발문 정답 비노출 준수율 ≥95%)

### 5.5 역할(모자) & 의식
- 모자: 교수설계·프롬프트 오너 / LLMOps·평가 오너 / 오케스트레이션·백엔드 오너 (1인 다모자 가능, 단 "이번 주 골든셋 책임자"는 명확히)
- 주간 의식 2개: **Trace 정독회**(실패→골든셋), **Eval 리뷰**(지표·회귀→배포결정)

## Part VI. 응용 콘텐츠 전략 (누적 데이터의 활용)

### 6.1 설계 원칙 (필터)
> 모든 응용 콘텐츠는 3경로(동기·학습효과·애착) 중 하나를 강화하되, **가능하면 "인출"을 내장**해야 한다. 보기만 하면 가짜 재방문, 다시 표현하게 하면 진짜 지속.

### 6.2 데이터 자산
- 삶 데이터(소재·개인데이터·시간) + 언어 수행 데이터(산출·채점·오개념·힌트) → **"삶 + 성장"의 시계열.**

### 6.3 3경로별 콘텐츠
- 🔵 학습효과: 개인화 복습 덱(미해소 오개념 간격 재출제), 나만의 표현 노트, 오개념 집중 드릴
- 🟣 애착: 영어로 보는 나의 한 해(+재인출), 성장 타임라인(then vs now), 나의 영어 기록집
- 🟢 동기: 나를 소개하는 스피치, 자기참조 롤플레이

### 6.4 우선순위
| 순위 | 콘텐츠 | 이유 |
|---|---|---|
| 1 | 개인화 복습 덱 | 데이터 즉시 활용, 학습효과 직접, ROI 최고 |
| 2 | 성장 타임라인 | 구현 쉬움, 자기효능감·애착 |
| 3 | 연간 회고 + 재인출 | 동기·학습·애착 삼중, 시그니처 후보 |

## Part VII. 실행 로드맵 (4개월 PoC)

축: **LLMOps-first** (측정 가능한 토대 위에 에이전트).

| | M1 | M2 | M3 | M4 |
|---|---|---|---|---|
| 층 | LLM 경화 + LLMOps 기반 | Agent v1 | Agent v2 | 검증·안정화 |
| 내용 | 진단 구조화, 프롬프트 외부화·버전화, Solar 연동, **골든셋 eval harness**, 품질 로깅, 회귀 게이트 | 소크라틱 루프(②): 진단→발문→재시도→해소 | 자기참조 RAG(③): 이력 검색→개인화 발문, 반복 오개념 재출제 | 측정 대시보드, 소규모 사용자 검증, PoC 리포트·데모 |
| 과제 | 세부① + 평가 인프라 | 세부② | 세부③ | 전체 |
| 종료 게이트 | **프롬프트 변경 시 진단 정확도 변화가 자동 측정됨** | 정답 비노출 준수율 ≥95%, end-to-end 루프 | 반복 오개념 탐지·발문 반영 | PoC 명제 입증 데이터 + 데모 |

상시 트랙: 계측(이벤트 로깅) + 골든셋 — M1부터.

리스크 & 디스코핑 레버(명제는 유지):
1. RAG는 개인화 발문까지만, 간격 재출제는 차기로
2. 오개념 taxonomy 7종 → 상위 3종(시제·관사·연어)으로 축소
3. 사용자 검증을 내부 N명 + 로그 분석으로 경량화

## Part VIII. 측정 & 성공기준

| 영역 | 지표 | 비고 |
|---|---|---|
| 진단 품질 | 오개념 분류 정확도(골든셋 대비) | 잠정 목표 ≥80% |
| 발문 품질 | 정답 비노출 준수율 / 소크라틱 후 자가 교정(해소)율 | ≥95% / 측정·관찰 |
| 학습효과(P2) | 백지 인출 성공률, 오개념 해소율(시간에 따른) | 자기 반복 주제 기준 |
| 지속(P1·P3) | 상태 전이(휴면→활성 복귀, 활성 장기유지), **인출 세션 비율, 오답 후 복귀율** | "학습 동반 지속" — 가짜 재방문 배제 |
| 애착(P3) | 누적 데이터량 ↔ 장기 리텐션(D30+) 상관 | 장기 경로 |

핵심: 재방문율·완주율 같은 표층 지표는 **단독으로 성공기준에 쓰지 않는다.** 학습이 내장된 지표로만 "학습 동반 지속"을 판정한다.

## 부록 A. 오개념 Taxonomy (한국어 화자 → 영어, 초안)
- `TENSE_ASPECT` 시제·상 (체계 차이로 최다)
- `ARTICLE` 관사 누락/오용 (L1에 관사 없음)
- `SUBJECT_DROP` 주어 생략 (L1 습관)
- `COUNTABILITY` 가산성/복수
- `PREPOSITION` 전치사 (조사→전치사 오매핑)
- `WORD_ORDER` 어순
- `LEXICAL_COLLOCATION` 직역체/연어
> 이 유형 분류가 발문 전략(②)·RAG 패턴탐지(③)·측정(해소율)을 모두 구동한다.

## 부록 B. 핵심 용어
- **자기참조성**: 학습 콘텐츠 소재가 학습자 자신에게서 비롯되는 정도(설계 속성).
- **인출**: 백지에서 산출하는 회상. 학습 자동화의 원천.
- **바람직한 어려움**: 학습효과를 낳는, 제거하면 안 되는 부하.
- **가짜 재방문**: 학습과 분리된 채 부풀려진 재방문(접속 습관).
- **학습 동반 지속**: 인출·해소가 내장된 상태 전이로 측정되는 지속.
- **확장된 자기**: 누적 기록이 정체성의 일부가 되어 애착을 형성하는 현상.
