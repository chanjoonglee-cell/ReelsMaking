# 언어의숲 레퍼럴(초대) 워크플로우

> 상태: v1 초안 · 최종수정 2026-05-31
> 모델: **기능 잠금형(Feature-Lock)** — 토스 "동그라미 챌린지" 구조 차용

---

## 1. 전략 배경 — 왜 "기능 잠금"인가

토스 메이커스 컨퍼런스(TMC25, 조성은 PO) 바이럴 케이스의 핵심 교훈:

> **바이럴 K = 공유 시도율 × 공유 성공률 × 인당 초대자 수**

| 단계 | 토스 액션 | 전략 | 결과 |
|------|-----------|------|------|
| Phase 0 | 친구도 나도 3천원 | "돈 줄 테니 **공유해**" (강요) | K=0.2 |
| Phase 1 | 동그라미 그리기 챌린지 | 재밌는 걸 주고, 더 하려면 공유 (공유할 **명분**) | K=0.4 |
| Phase 2 | 1천만원 복권 | 받는 친구의 **기대감** 생성 | 공유 성공률 ↑ |

**두 가지 결론:**
1. **"공유시키기 → 공유하고 싶게 만들기"** — 돈으로 강요하면 K=0.2에서 정체. 진짜 즐기는 걸 주고, 계속하려면 자연스럽게 공유하게 만든다.
2. **받는 사람의 기대감** — 링크는 뿌려져도 친구가 안 열어봄. 열어서 얻을 게 없으니까.

### 언어의숲의 결정적 이점

토스는 공유 명분(동그라미)·기대감(복권)을 **발명**해야 했지만, 언어의숲은 이미 **"영어 일기 릴스"라는 공유 본능을 자극하는 결과물**을 만든다.

- **명분** = 내가 만든 릴스는 원래 자랑/공유하고 싶음
- **기대감** = 친구가 받는 게 맨 초대 링크가 아니라 *"내가 만든 영어 일기 영상"* → 안 열 수 없음

→ 따라서 **공유 트리거를 "릴스 저장/내보내기" 라는 제품 경험 안에 박아 넣는다.**

## 2. 핵심 메커니즘 (Feature-Lock)

### 게이트 위치 — "아하 모먼트는 먼저, 게이트는 그 다음"

토스가 동그라미를 **먼저 그리게 하고(성공 경험)** 그 다음 "다시 하려면 공유"로 막았던 것처럼, 첫 성공 경험은 절대 막지 않는다.

| 액션 | 무료 유저 | 게이트 |
|------|-----------|--------|
| 릴스 **생성 + 미리보기** | ✅ 항상 무료 | 없음 (아하 모먼트) |
| **워터마크 포함** 공유 (인스타/카톡) | ✅ 무료 | 없음 (워터마크 = 바이럴 매개체) |
| **워터마크 제거 + HD 저장(카메라롤)** | 🔒 잠금 | **친구 1명 초대 성공** 시 해제 |
| **2번째 릴스부터** 생성 | 🔒 잠금 | 초대 성공 / 구독 |

> 핵심: 무료 공유 영상에 **워터마크 + 딥링크**를 박아 둔다. 워터마크가 브랜드와 초대 링크를 친구 피드로 실어 나르는 **바이럴 캐리어** 역할 → 워터마크는 막아야 할 누수가 아니라 의도된 성장 채널.

### 초대 "성공"의 정의 (2단계)

1. **1차 해제 (피추천인 가입 + 첫 릴스 생성)** → 추천인의 *워터마크 제거/HD 저장* 기능 해제
2. **자격 충족 (피추천인 첫 유료 결제)** → 추천인·피추천인 **양방향 구독 기간 보상** (Phase 0 바닥 보상)

이렇게 하면 "기능 해제(빠른 보람)" + "구독 보상(전환 유인)"이 2단으로 쌓인다.

## 3. 유저 플로우

```
[추천인]                         [시스템]                        [피추천인]
   │ 1. 릴스 생성·미리보기(무료) ──▶│                               │
   │   "저장/워터마크 제거" 누름     │                               │
   │◀── 🔒 "친구 1명 초대하면 해제"  │                               │
   │ 2. 초대코드+딥링크 공유 ───────────────────────────────────────▶│
   │   (워터마크 영상 함께 전송)      │   3. 딥링크 클릭(영상 미리보기) │
   │                                │◀── 앱 설치/열기, 코드 자동귀속  │
   │                                │   4. "너도 무료로 만들어봐" 체험 │
   │                                │◀── 5. 가입 + 첫 릴스 생성 ──────│
   │◀── 6. 워터마크 제거/HD 해제 ────│   ▶ [1차 해제]                 │
   │       + 푸시 "○○님이 가입!"     │                               │
   │                                │◀── 7. 첫 유료 결제 ────────────│
   │◀── 8. 구독 기간 보상 지급 ──────│   ▶ [자격충족] 양방향 보상      │
   │                                │   ▶ 피추천인도 구독 보상        │
```

### 상태(State) 머신

```
코드발급 → 클릭/귀속(attributed) → 가입+첫릴스(signed_up)
  → [1차 해제] → 첫결제(qualified) → 보상지급(rewarded)
  → (환불/취소 시) 회수(reverted)
```

## 5. 어뷰징 방어 (필수)

- **자기 초대 차단** — 동일 기기 ID / 결제수단 / IP 군집 → 무효
- **신규 유저만 피추천인 자격** — 기존 가입 이력 있으면 보상 X
- **어트리뷰션 기간 제한** — 클릭 후 30일 내 가입만 인정
- **추천인 보상 상한(cap)** — 예: 월 최대 N명, 누적 최대 12개월치
- **환불/구독취소 시 보상 회수** — `reverted` 처리, 기능 해제·구독 보상 회수
- **결제 웹훅 멱등성** — 중복 수신 시 보상 중복 지급 방지 (idempotency key)
- **1차 해제(가입)와 자격충족(결제) 분리** — 가짜 가입으로 구독 보상까지 못 받게

## 6. 측정 지표 (Mixpanel 등)

바이럴 K를 항(項)별로 추적해 어느 레버가 막혔는지 본다.

| 레버 | 이벤트 | 지표 |
|------|--------|------|
| 공유 시도율 | `reel_export_gated`, `invite_shared` | 게이트 노출 → 공유 클릭 전환율 |
| 공유 성공률 | `invite_link_opened`, `referee_signup` | 링크 열람률, 가입 전환율 |
| 인당 초대자 수 | `referral_qualified` | 추천인당 평균 자격충족 수 |
| 종합 | — | **K = 공유시도율 × 공유성공률 × 인당초대자수** |

퍼널: `reel_created → export_gated → invite_shared → link_opened → referee_signup → first_reel → first_payment`

## 7. 결정 필요한 오픈 이슈

1. **게이트 강도** — 워터마크 제거만 막을지, 2번째 릴스 생성부터 막을지 (마찰 vs K 트레이드오프). → A/B 테스트 권장
2. **구독 보상 크기** — 추천인/피추천인 각각 며칠? (예: 각 14일 또는 1개월)
3. **딥링크 인프라** — Branch.io / AppsFlyer / 자체 구현? (Firebase Dynamic Links는 2025 종료)
4. **플랫폼·결제** — 네이티브/RN·Flutter? IAP vs 자체 PG? (보상 회수 로직이 결제 채널에 종속)
5. **상한값** — 추천인 월 최대 초대 수, 누적 보상 상한

---

## 8. 구현 단계 (제안)

- **MVP (1차)**: 코드/딥링크 발급 + 귀속, 워터마크 제거 게이트, 1차 해제까지. 어트리뷰션·자기초대 차단 포함.
- **2차**: 첫 결제 자격충족 → 양방향 구독 보상, 환불 회수 로직, 멱등성.
- **3차**: Mixpanel K 퍼널 대시보드, 게이트 강도 A/B 테스트, 상한·이상탐지.
